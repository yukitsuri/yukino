# Функции и замыкания

## 1. Объявление функций

### 1.1 Базовый синтаксис

Функции объявляются с помощью ключевого слова `fun`. Тип возвращаемого значения указывается через стрелку `->`. Если тип не указан, функция возвращает `void`:

```yukino
// Функция с явным типом возврата
fun multiply(a: int32, b: int32) -> int32 {
    return a * b
}

// Процедура без возвращаемого значения (void)
fun log_event(message: string) {
    // Внутренние операции
}
```

Если тело функции временно не содержит реализации, используйте ключевое слово `space`, чтобы избежать предупреждения компилятора:

```yukino
fun placeholder_handler() {
    space
}
```

### 1.2 Параметры со значениями по умолчанию

Параметры могут иметь значения по умолчанию, которые подставляются компилятором на этапе десахаризации вызова:

```yukino
fun connect(host: string, port: int32 = 8080, secure: bool = true) -> bool {
    // Логика подключения
    return true
}

// Допустимые варианты вызова:
set r1 = connect("127.0.0.1")                    // port=8080, secure=true
set r2 = connect("127.0.0.1", 9000)              // secure=true
set r3 = connect("127.0.0.1", 9000, false)       // все параметры переданы явно
```

### 1.3 Способы передачи аргументов

- **По значению**: элементарные Copy-типы дублируются; Affine-типы передают владение.
- **По неизменяемой ссылке (`ref param: T`)**: для эффективной передачи тяжелых структур без копирования и без передачи владения (в месте вызова: `ref arg`).
- **По изменяемой ссылке (`ref ~param: T`)**: для изменения состояния переданного объекта на месте (в месте вызова: `ref ~arg`).

```yukino
struct Matrix {
    data: float64[]
}

fun inspect(ref m: Matrix) {
    // Только чтение
}

fun reset(ref ~m: Matrix) {
    // Модификация
}
```

### 1.4 Именованные аргументы

При вызове функций аргументы могут передаваться по имени с помощью синтаксиса `имя = значение`. Это позволяет передавать аргументы в произвольном порядке и гибко комбинировать их с параметрами по умолчанию:

```yukino
fun configure(host: string, port: int32 = 8080, secure: bool = true) -> string {
    return "${host}:${port}"
}

// Именованные аргументы в произвольном порядке:
set c1 = configure(host = "localhost", secure = false)

// Комбинация позиционных и именованных аргументов:
set c2 = configure("127.0.0.1", secure = true, port = 9000)
```

### 1.5 Вариативные параметры (variadics) и оператор spread

Функция может принимать переменное число аргументов одного типа. Для этого перед именем последнего параметра указывается многоточие `...`:

```yukino
fun sum(...numbers: int64) -> int64 {
    set total = 0
    for i in 0..numbers.len() {
        rewrite total += numbers[i]
    }
    return total
}
```

Правила и ограничения:
- Внутри тела функции вариативный параметр доступен как массив соответствующего типа (`numbers: int64[]`).
- Вариативный параметр **обязан быть последним** в списке параметров функции.
- Вариативный параметр **не может** иметь значения по умолчанию.
- Вариативные параметры запрещены для функций C ABI (`cfun`).

Вызовы вариативной функции:

```yukino
// Передача произвольного количества аргументов:
set s0 = sum()              // numbers = []
set s1 = sum(5)             // numbers = [5]
set s3 = sum(1, 2, 3)       // numbers = [1, 2, 3]

// Разворачивание существующего массива через оператор spread (...):
set items = [10, 20, 30]
set s_all = sum(...items)   // numbers = [10, 20, 30]
```

## 2. Анонимные функции и замыкания (closures)

В соответствии с философией явности и предсказуемости Yukino, объявление анонимных функций и замыканий всегда начинается с ключевого слова `fun`.

### 2.1 Синтаксис

Yukino поддерживает краткую стрелочную форму с телом-выражением `=>` и полную форму с блоком `{ ... }`:

```yukino
// Стрелочная запись (тело — выражение):
set add = fun(a: int32, b: int32) => a + b
set inc = fun(x: int32) => x + 1
set zero = fun() => 0

// Полная форма с блоком и явным return:
set mul = fun(x: int32) -> int32 {
    return x * 3
}

// Передача замыкания аргументом в функцию:
println("${apply(fun(x: int32) => x + 10, 5)}")
```

При стрелочной записи `fun(...) => expr` тип возвращаемого значения выводится автоматически из результирующего выражения. В блочной форме `fun(...) -> RetType { ... }` тип возврата может быть указан явно либо выведен из оператора `return`.

### 2.2 Захват лексического окружения

Замыкание может ссылаться на переменные внешнего лексического окружения:

```yukino
set base: int32 = 100
set add_base = fun(x: int32) => base + x

println("${add_base(5)}") // 105
```

Кодогенератор Yukino автоматически выявляет свободные переменные и формирует компактную структуру окружения (`environment`), в которую копируются захваченные значения. Сама структура размещается в региональной памяти через быструю bump-аллокацию.

### 2.3 Внутреннее устройство: fat-указатель

В памяти замыкание представлено fat-указателем из двух машинных слов:

```text
Замыкание: { fn: указатель на код, env: указатель на структуру окружения }
```

Вызов замыкания — косвенный вызов по указателю на код с соглашением `fastcall`; указатель окружения передается как скрытый аргумент, и код замыкания распаковывает захваченные значения из структуры окружения. Если замыкание не захватывает переменных окружения, указатель `env` равен `null`. При приведении именованной функции верхнего уровня к типу замыкания компилятор автоматически генерирует thunk-адаптер.

## 3. Функциональные типы и указатели на функции

В Yukino типы функций объявляются с помощью ключевых слов `fun` и `cfun`:

- `fun(T1, T2, ...) -> RetType` — тип функции со стандартным соглашением вызова Yukino (`fastcall`).
- `cfun(T1, T2, ...) -> RetType` — указатель на функцию со стандартным соглашением вызова C ABI (`cdecl`).

### 3.1 Передача функций в качестве значений

Функции с соглашением `cfun` могут присваиваться переменным и вызываться косвенно:

```yukino
cfun add(a: int32, b: int32) -> int32 {
    return a + b
}

cfun multiply(a: int32, b: int32) -> int32 {
    return a * b
}

// Прием функции как аргумента
fun apply_op(f: cfun(int32, int32) -> int32, x: int32, y: int32) -> int32 {
    return f(x, y)
}

// Передача функции
set op: cfun(int32, int32) -> int32 = add
set res = apply_op(op, 10, 20) // 30
```

## 4. Манглинг имен функций

Все функции, объявленные через ключевое слово `fun`, автоматически манглятся компилятором в LLVM IR в детерминированные символы вида:

```text
__yukifun_{имя}_{типы_аргументов_через_подчеркивание}__{тип_возврата}
```

Если у функции нет аргументов, разделителем служит тройное подчеркивание `___`:

```text
__yukifun_{имя}___{тип_возврата}
```

Примеры:
- `fun add(a: int32, b: int32) -> int32` компилируется в символ `@__yukifun_add_int32_int32__int32`
- `fun get_count() -> int64` компилируется в символ `@__yukifun_get_count___int64`
- `fun run()` компилируется в символ `@__yukifun_run___void`

Исключения и управление:
- Главная точка входа `fun main` никогда не манглится и всегда экспортируется как `@main`.
- Для отключения манглинга у Yukino-функции используется атрибут `#[!mangle]`: такой функции присваивается точное исходное имя символа.
- Функции с соглашением C ABI (`cfun`) по умолчанию не манглятся, обеспечивая прямую совместимость с C. Для включения манглинга у `cfun` используется атрибут `#[mangle]`.
