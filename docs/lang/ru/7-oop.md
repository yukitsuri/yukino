# Структуры, классы и интерфейсы

## 1. Структуры (struct) — типы-значения

Структуры в Yukino — это легковесные типы-значения (value types) с прямым представлением в памяти (C-совместимый layout). Они располагаются непосредственно на стеке или встраиваются в память объемлющих структур без заголовков объектов и vtable. Структуры в Yukino предназначены исключительно для хранения и передачи данных (включая структуры ошибок в `panic`, аргументы функций и возвращаемые значения).

### 1.1 Объявление и создание

```yukino
struct Point {
    x: float64,
    y: float64
}

// Создание экземпляра через литерал структуры
set pt = Point { x: 10.0, y: 20.0 }

// Чтение полей (рекомендуется указывать тип для явности)
set px: float64 = pt.x
set py: float64 = pt.y
```

> [!NOTE]
> В Yukino структуры (`struct`) используются исключительно для хранения и передачи чистых данных с нулевыми накладными расходами (например, типизированные ошибки `panic(Error { ... })`, передача составных аргументов и возврат нескольких значений). Они не содержат методов, конструкторов или логики поведения. Для объектно-ориентированной модели с методами, наследованием и полиморфизмом используются классы (`class`).

## 2. Классы (class) — ссылочные типы

Классы — это полиморфные сущности, управляемые региональной моделью памяти. Они поддерживают конструкторы, одиночное наследование, переопределение методов и динамическую диспетчеризацию через таблицы виртуальных методов (vtable).

### 2.1 Объявление и конструкторы

Создание экземпляра класса происходит с помощью ключевого слова `init`: `init ClassName(...)`, что активирует метод `init`:

```yukino
class Animal {
    name: string

    fun init(name: string) {
        rewrite this.name = name
    }

    fun speak() -> string {
        return "..."
    }

    fun describe() -> string {
        return this.name
    }
}

// Создание экземпляра с использованием init
set pet = init Animal("Barsik")
set voice = pet.speak()
```

### 2.2 Заблокированные классы: locked class

Модификатор `locked` запрещает наследование от класса. Попытка создать подкласс приводит к ошибке компиляции (`E0409`):

```yukino
locked class GuardService {
    active: bool

    fun init(active: bool) {
        rewrite this.active = active
    }
}

// ОШИБКА: E0409 (cannot inherit from locked class)
// class CustomGuard extends GuardService {}
```

### 2.3 Наследование и ключевое слово super

Классы расширяют базовый класс через `extends`. Ключевое слово `super` позволяет вызвать конструктор предка и обратиться к его методам:

```yukino
class Dog extends Animal {
    breed: string

    fun init(name: string, breed: string) {
        // Вызов конструктора базового класса
        super(name)
        rewrite this.breed = breed
    }

    // Переопределение виртуального метода
    fun speak() -> string {
        return "Woof!"
    }
}

set dog = init Dog("Rex", "Collie")
set sound = dog.speak() // "Woof!"
```

### 2.4 Параметры-ссылки в методах

Методы классов принимают параметры-ссылки `ref T` и `ref ~T` с той же семантикой, что и обычные функции (подробнее — в главе «Модель памяти, владение и регионы»): `ref` дает совместное чтение, `ref ~` — эксклюзивную запись на месте. Ссылка передается явно в месте вызова, владение объектом не перемещается.

```yukino
struct Counter {
    value: int64
}

class Accumulator {
    step: int64

    fun init(step: int64) {
        rewrite this.step = step
    }

    fun add(ref ~c: Counter) {
        rewrite c.value = c.value + this.step
    }

    fun peek(ref c: Counter) -> int64 {
        return c.value
    }
}

set acc = init Accumulator(5)
set c = Counter { value: 10 }
acc.add(ref ~c)
set v: int64 = acc.peek(ref c) // 15
```

Через `ref ~` метод может изменять не только собственные поля, но и переданный объект вызывающего кода; `ref` гарантирует вызывающей стороне, что объект останется неизменным.

## 3. Свойства: get и set аксессоры

Классы поддерживают вычисляемые свойства с помощью синтаксиса `get` и `set`:

```yukino
class Rectangle {
    w: float64
    h: float64

    fun init(w: float64, h: float64) {
        rewrite this.w = w
        rewrite this.h = h
    }

    // Геттер
    get area() -> float64 {
        return this.w * this.h
    }

    // Сеттер
    set size(val: float64) {
        rewrite this.w = val
        rewrite this.h = val
    }
}

set rect = init Rectangle(10.0, 5.0)
set a: float64 = rect.area // Вызов геттера

// Запись в сеттер требует rewrite
rewrite rect.size = 20.0
```

## 4. Перегрузка операторов

Классы могут перегружать операторы через ключевое слово `operator`. Доступны:

- арифметические: `+`, `-`, `*`, `/`, `%`, `**`;
- побитовые операции и сдвиги: `&`, `|`, `^`, `~`, `<<`, `>>`;
- сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`;
- унарные: `!`, `~`, а также унарный минус (метод `operator -` без параметров);
- индексация: `[]` и `[]=`.

Если определен только `==`, компилятор автоматически выводит `!=` как отрицание результата `==`. Диспетчеризация перегруженных операторов реализована для операндов-классов.

```yukino
class Complex {
    re: float64
    im: float64

    fun init(re: float64, im: float64) {
        rewrite this.re = re
        rewrite this.im = im
    }

    operator +(other: Complex) -> Complex {
        return init Complex(this.re + other.re, this.im + other.im)
    }

    operator ==(other: Complex) -> bool {
        return this.re == other.re && this.im == other.im
    }
}

set c1 = init Complex(1.0, 2.0)
set c2 = init Complex(3.0, 4.0)
set c3 = c1 + c2 // Вызывает operator +
```

## 5. Интерфейсы (interface)

Интерфейсы объявляют контракты методов, которые класс обязуется реализовать. Классы декларируют реализацию с помощью ключевого слова `with`:

```yukino
interface Describable {
    fun describe() -> string
}

class Item with Describable {
    title: string

    fun init(title: string) {
        rewrite this.title = title
    }

    fun describe() -> string {
        return this.title
    }
}

fun print_description(d: Describable) {
    println(d.describe())
}
```

> [!NOTE]
> Typechecker гарантирует, что класс, реализующий интерфейс (`with InterfaceName`), содержит все требуемые методы с правильными сигнатурами. При вызове методов через интерфейсную переменную компилятор выполняет динамическую диспетчеризацию через таблицу интерфейсных методов `itable`.

### 5.1 Обобщенные интерфейсы (Generic Interfaces)

Интерфейсы могут объявлять параметры типов (`interface Name<T>` или `interface Name<T, R>`):

```yukino
interface Box<T> {
    fun set_val(v: T) -> int32
    fun get_val() -> T
}

class StringBox with Box<string> {
    item: string

    fun set_val(v: string) -> int32 {
        rewrite this.item = v
        return 0
    }

    fun get_val() -> string {
        return this.item
    }
}

fun print_box(b: Box<string>) {
    println(b.get_val())
}
```

Класс реализует обобщенный интерфейс с указанием конкретных аргументов типов (`with Box<string>`). При вызове методов через интерфейсную переменную компилятор генерирует динамическую диспетчеризацию через `itable` с проверкой типов на этапе компиляции.

## 6. Перечисления (enum)

Перечисления (`enum`) в Yukino представляют собой типы-значения с дискриминированным тегом. Они позволяют задавать закрытый набор возможных состояний и объединять простые числовые метки с богатыми алгебраическими типами данных (ADT / Tagged Unions).

### 6.1 Объявление и разновидности вариантов

Yukino поддерживает три разновидности вариантов внутри перечисления:

1. **Простые варианты (Simple)**:
   Именованные константы без полезной нагрузки. Компилятор автоматически назначает каждому варианту последовательный целочисленный тег, начиная с нуля:

   ```yukino
   enum Color {
       Red,
       Green,
       Blue
   }
   ```

2. **Варианты со значениями (WithValue)**:
   Варианты с явно заданными целочисленными константами. Удобны для кодов протоколов, системных ошибок и битовых флагов:

   ```yukino
   enum HttpStatus {
       Ok = 200,
       Created = 201,
       BadRequest = 400,
       NotFound = 404,
       ServerError = 500
   }
   ```

3. **ADT-варианты с полезной нагрузкой (Adt)**:
   Варианты, несущие типизированные поля данных в круглых скобках. Разные варианты одного перечисления могут содержать разное количество полей различных типов или не содержать их вовсе:

   ```yukino
   enum WebEvent {
       PageLoad,
       KeyPress(key: char),
       Click(x: int64, y: int64),
       Message(text: string)
   }
   ```

### 6.2 Создание и использование значений

Создание экземпляров перечисления выполняется с использованием квалифицированного пути `EnumName::Variant`:

```yukino
// Простые варианты
set c: Color = Color::Red

// Варианты с числовым значением
set status: HttpStatus = HttpStatus::Ok

// Варианты с полезной нагрузкой (ADT)
set ev_load: WebEvent = WebEvent::PageLoad
set ev_key: WebEvent = WebEvent::KeyPress('Q')
set ev_click: WebEvent = WebEvent::Click(100, 200)
set ev_msg: WebEvent = WebEvent::Message("соединение установлено")
```

### 6.3 Сопоставление с образцом в switch

Перечисления наиболее полно раскрываются в сочетании с конструкцией `switch`. В Yukino ветки `switch` не требуют ключевого слова `case` и записываются в виде `Шаблон -> { тело }`.

#### Проверка полноты (Exhaustiveness checking)

Компилятор строго отслеживает полноту сопоставления. Если в `switch` без ветки `else ->` не покрыты все варианты перечисления, компилятор останавливает сборку с ошибкой `E0405`:

```yukino
set color = Color::Green

// Все варианты Color покрыты — проверка проходит успешно
switch color {
    Color::Red -> {
        println("Остановка")
    }
    Color::Green -> {
        println("Движение")
    }
    Color::Blue -> {
        println("Внимание")
    }
}
```

#### Ветка по умолчанию (else ->) и объединение вариантов (|)

Если требуется обработать только подмножество вариантов, оставшиеся можно перехватить через ветку `else ->`. Несколько вариантов с одинаковой логикой объединяются оператором `|`:

```yukino
set status = HttpStatus::NotFound

switch status {
    HttpStatus::Ok | HttpStatus::Created -> {
        println("Успешный статус")
    }
    HttpStatus::NotFound -> {
        println("Ресурс не найден")
    }
    else -> {
        println("Другой код состояния")
    }
}
```

> [!NOTE]
> Любой шаблон, размещенный после ветки `else ->` или шаблона-подстановки `_`, считается недостижимым и приводит к ошибке компиляции `E0406`.

#### Деструктуризация полей полезной нагрузки (ADT)

При сопоставлении вариантов с полезной нагрузкой поля автоматически распаковываются в переменные внутри соответствующей ветки:

```yukino
set event = WebEvent::Click(1024, 768)

switch event {
    WebEvent::PageLoad -> {
        println("Страница полностью загружена")
    }
    WebEvent::KeyPress(k) -> {
        println("Пользователь нажал клавишу: " + cast(k, "string"))
    }
    WebEvent::Click(x, y) -> {
        println("Клик мыши в точке: (${x}, ${y})")
    }
    WebEvent::Message(msg) -> {
        println("Входящее сообщение: " + msg)
    }
}
```

#### Охранные выражения (guards)

К шаблону варианта можно добавить дополнительное логическое условие через ключевое слово `if`:

```yukino
switch event {
    WebEvent::Click(x, y) if x < 0 || y < 0 -> {
        println("Клик за пределами активной области")
    }
    WebEvent::Click(x, y) -> {
        println("Клик в рабочей зоне: (${x}, ${y})")
    }
    else -> {}
}
```

### 6.4 Модель памяти и сравнение

`enum` в Yukino является типом-значением (value type) с разметкой размеченного объединения (tagged union):
- Поле тега дискриминанта (`i32`, 4 байта), определяющее активный вариант.
- Байтовый буфер `[N x i8]` под полезную нагрузку, выровненный по максимальному выравниванию полей. Размер `N` равен максимальному размеру полезной нагрузки среди всех вариантов данного перечисления (для простых перечислений `N = 0`).

Перечисления размещаются непосредственно на стеке или встраиваются в память структур. Экземпляры одного и того же перечисления поддерживают операторы сравнения на равенство `==` и неравенство `!=`:

```yukino
set current_state = Color::Red
set target_state = Color::Green

if current_state == target_state {
    println("Состояния совпадают")
} else if current_state != Color::Blue {
    println("Текущее состояние отличается от Blue")
}
```
