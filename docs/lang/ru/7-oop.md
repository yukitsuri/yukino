## 1. Структуры (struct) — типы-значения

Структуры в Yukino — это легковесные типы-значения (value types) с прямым представлением в памяти (C-совместимый layout). Они располагаются непосредственно на стеке или встраиваются в память объемлющих структур без заголовков объектов и vtable. Структуры в Yukino предназначены исключительно для хранения и передачи данных (включая структуры ошибок в `panic`, аргументы функций и возвращаемые значения).

### 1.1 Объявление и создание

```yukino
struct Point {
    x: float64,
    y: float64
}

// Создание экземпляра через литерал структуры
set pt = Point { x: 10.0, y: 20.0 }

// Чтение полей (рекомендуется указывать тип для явности)
set px: float64 = pt.x
set py: float64 = pt.y
```

#### Правила объявления и валидации структур:

1. **Уникальность полей при объявлении**: имена полей внутри структуры обязаны быть уникальными. Повторное объявление поля с тем же именем приводит к ошибке компиляции `E0304` (duplicate field).
2. **Существование типа структуры**: попытка создать экземпляр необъявленной структуры приводит к ошибке компиляции `E0305` (unknown type/struct).
3. **Обязательная инициализация всех полей**: в литерале структуры должны быть инициализированы все объявленные поля. Пропуск любого поля вызывает ошибку компиляции `E0401` (missing required field).
4. **Запрет неизвестных полей**: указание в литерале полей, не объявленных в структуре, приводит к ошибке компиляции `E0401` (unknown field).
5. **Запрет дубликатов полей в литерале**: повторное указание одного и того же поля в одном инициализаторе вызывает ошибку компиляции `E0401` (duplicate field in struct initializer).
6. **Контроль типов полей**: тип каждого выражения, переданного полю, строго проверяется на соответствие объявленному типу поля структуры. Несовпадение типов вызывает ошибку компиляции `E0401` (type mismatch) с поясняющей контекстной заметкой.

> [!NOTE]
> В Yukino структуры (`struct`) используются исключительно для хранения и передачи чистых данных с нулевыми накладными расходами (например, типизированные ошибки `panic(Error { ... })`, передача составных аргументов и возврат нескольких значений). Они не содержат методов, конструкторов или логики поведения. Для объектно-ориентированной модели с методами, наследованием и полиморфизмом используются классы (`class`).

## 2. Классы (class) — ссылочные типы

Классы — это полиморфные сущности, управляемые региональной моделью памяти. Они поддерживают конструкторы, одиночное наследование, переопределение методов и динамическую диспетчеризацию через таблицы виртуальных методов (vtable).

### 2.1 Объявление и конструкторы

Создание экземпляра класса происходит с помощью ключевого слова `init`: `init ClassName(...)`. Попытка создать экземпляр вызовом `ClassName(...)` без `init` приводит к ошибке компиляции `E0401`:

```yukino
class Animal {
    name: string

    fun init(name: string) {
        rewrite this.name = name
    }

    fun speak() -> string {
        return "..."
    }

    fun describe() -> string {
        return this.name
    }
}

// Создание экземпляра с использованием init
set pet = init Animal("Barsik")
set voice = pet.speak()
```

#### Тонкости инициализации и конструктора `init`:

1. **Порядок создания экземпляра**: выражение `init ClassName(...)` сначала выделяет память под объект (в активном регионе или на стеке при элизии региона), **детерминированно обнуляет все экземплярные поля** (включая унаследованные), записывает указатель на таблицу виртуальных методов `vtable`, применяет **стартовые литеральные значения полей** (`field: T = <literal>`) в порядке предки -> наследник и лишь затем вызывает метод `init`.
2. **Стартовые значения полей**: любое обычное поле класса можно инициализировать литералом по умолчанию: `port: int32 = 8080` или `set port: int32 = 8080` (ключевое слово `set` перед полем опционально и полностью эквивалентно обычному объявлению). В качестве значения по умолчанию принимаются только литералы (включая унарный минус/отрицание на литерале); нелитеральные выражения вызывают ошибку `E0401`.
3. **Статические поля класса (`static`)**: объявление `static FIELD: T = <literal>` задает неизменяемое общее поле класса без выделения памяти в каждом экземпляре (хранится как константа и учитывает настройку `inline_statics`). Для `static`-поля стартовый литерал **обязателен**. Доступ к `static`-полю выполняется так же, как к обычному полю (`this.FIELD`, `super.FIELD`, `obj.FIELD`), за исключением того, что попытка изменения через `rewrite` приводит к ошибке компиляции `E0503`.
4. **Наследование `init` и отсутствие конструктора**: если подкласс не объявляет собственный `init`, он автоматически наследует конструктор ближайшего предка, у которого `init` определен. Если конструктора нет ни в одном классе иерархии, `init ClassName()` вызывается без аргументов (передача аргументов дает ошибку `E0401`).
5. **Возвращаемое значение в `init`**: метод `init` инициализирует уже выделенный экземпляр `this` и по умолчанию имеет тип возврата `void`. Пустой `return` внутри `init` допустим для раннего выхода, а `return this` при сигнатуре без `-> Type` вызовет ошибку `E0401` (`init ClassName(...)` возвращает созданный объект автоматически).
6. **Модификатор видимости**: для экспорта полей и методов за пределы модуля используется модификатор `public` (например, `public static MAX: int32 = 16`).

### 2.2 Заблокированные классы: locked class

Модификатор `locked` запрещает наследование от класса. Попытка создать подкласс приводит к ошибке компиляции (`E0409`):

```yukino
locked class GuardService {
    active: bool

    fun init(active: bool) {
        rewrite this.active = active
    }
}

// ОШИБКА: E0409 (cannot inherit from locked class)
// class CustomGuard extends GuardService {}
```

### 2.3 Наследование и ключевое слово super

Классы расширяют базовый класс через `extends` (поддерживается одиночное наследование). Поля предка размещаются перед собственными полями наследника. Ключевое слово `super` работает в нескольких формах:

```yukino
class Dog extends Animal {
    breed: string

    fun init(name: string, breed: string) {
        // Статический вызов конструктора базового класса
        super(name)
        rewrite this.breed = breed
    }

    // Переопределение виртуального метода
    fun speak() -> string {
        // Прямой вызов реализации предка в обход vtable и чтение поля предка
        return super.speak() + " Woof (" + super.name + ")"
    }

    fun as_animal() -> Animal {
        // Восходящее представление текущего экземпляра this как Animal
        return super
    }
}

set dog = init Dog("Rex", "Collie")
set sound = dog.speak() // "... Woof (Rex)"
```

#### Все формы `super` и их точная семантика:

1. **`super(аргументы...)` — вызов конструктора предка**:
   - Статически вызывает метод `init` ближайшего предка с передачей текущего указателя `this` (новый объект не выделяется).
   - **Неявного вызова нет**: если подкласс определяет собственный `init`, компилятор не вызывает `super(...)` автоматически. Без явного `super(...)` поля предка остаются обнуленными.
   - Если у предков нет метода `init`, вызов `super(...)` завершается ошибкой `E0416`.

2. **`super.method(аргументы...)` — статический вызов метода предка**:
   - Находит метод в ближайшем базовом классе и вызывает его **напрямую, в обход `vtable`**, передавая `this`. Это позволяет расширить переопределенный метод родительской реализацией без бесконечной рекурсии. При отсутствии метода в предке выдается ошибка `E0416`.

3. **`super.field` и `rewrite super.field = значение` — доступ к полям предка**:
   - Читает или изменяет поле/аксессор базового класса на текущем экземпляре `this` (ошибка `E0416`, если поле не найдено в иерархии предка).

4. **Пустой (одиночный) `super` без скобок и точки**:
   - Как выражение (`set base = super`, `return super`, передача в функцию), одиночный `super` вычисляется в **тот же самый указатель `this`**, но имеет статический тип прямого базового класса (восходящее приведение `upcast`).
   - **Важно**: голый `super` отдельной строкой в теле метода (без `()`) **НЕ вызывает конструктор предка**! Он разбирается как выражение-инструкция, результат которого отбрасывается (пустая операция во время выполнения), хотя компилятор все равно проверяет контекст метода и наличие предка (`E0416`). Для вызова конструктора базового класса без параметров обязательно пишите скобки: `super()`.

> [!NOTE]
> Любое использование `super` вне метода класса или внутри класса, у которого нет базового класса (`extends`), приводит к ошибке компиляции `E0416`.

### 2.4 Параметры-ссылки в методах

Методы классов принимают параметры-ссылки `ref T` и `ref ~T` с той же семантикой, что и обычные функции (подробнее — в главе «Модель памяти, владение и регионы»): `ref` дает совместное чтение, `ref ~` — эксклюзивную запись на месте. Ссылка передается явно в месте вызова, владение объектом не перемещается.

```yukino
struct Counter {
    value: int64
}

class Accumulator {
    step: int64

    fun init(step: int64) {
        rewrite this.step = step
    }

    fun add(ref ~c: Counter) {
        rewrite c.value = c.value + this.step
    }

    fun peek(ref c: Counter) -> int64 {
        return c.value
    }
}

set acc = init Accumulator(5)
set c = Counter { value: 10 }
acc.add(ref ~c)
set v: int64 = acc.peek(ref c) // 15
```

Через `ref ~` метод может изменять не только собственные поля, но и переданный объект вызывающего кода; `ref` гарантирует вызывающей стороне, что объект останется неизменным.

### 2.5 Ключевое слово this, ref this и return this

Внутри методов и аксессоров класса всегда доступен идентификатор `this` — ссылка на текущий экземпляр со статическим типом этого класса.

#### Явное и неявное указание `this` в параметрах:

- Если `this` в списке параметров опущен (`fun bump(step: int64)`), компилятор автоматически добавляет его как обычный параметр получателя.
- Получателя можно указать явно: `fun bump(this, step: int64)` или как общее заимствование `fun peek(ref this) -> int64`.
- Саму переменную `this` нельзя перепривязать (`rewrite this = ...`), но поля текущего экземпляра можно свободно изменять через `rewrite this.field = ...` (вызов метода на объекте `obj.method()` не перемещает владение переменной `obj`).

#### Что делает `return this`:

Инструкция `return this` возвращает указатель на **тот же самый экземпляр объекта**, не копируя структуру и не выделяя новую память. Это позволяет строить цепочки вызовов (fluent builder API):

```yukino
class RequestBuilder {
    host: string
    port: int64

    fun init() {
        rewrite this.host = "localhost"
        rewrite this.port = 80
    }

    fun with_host(host: string) -> RequestBuilder {
        rewrite this.host = host
        return this
    }

    fun with_port(port: int64) -> RequestBuilder {
        rewrite this.port = port
        return this
    }

    fun get_port(ref this) -> int64 {
        return this.port
    }
}

set req = init RequestBuilder()
    .with_host("example.com")
    .with_port(443)
set p: int64 = req.get_port() // 443
```

При использовании `return this` важно учитывать:
- Метод обязан явно объявить совместимый тип возврата (`-> RequestBuilder`, базовый класс через `-> BaseClass` или реализованный интерфейс через `-> InterfaceName`).
- `return this` не перемещает и не инвалидирует `this` внутри самого метода: до `return this` и при подготовке возвращаемого значения поля объекта остаются полностью доступными.
- Обычные вызовы методов класса выполняются виртуально через `vtable` (а через переменную интерфейсного типа — через `itable`), в отличие от статических вызовов `super(...)` и `super.method(...)`.

### 2.6 Поля класса: set, static и начальные значения

Поля класса можно объявлять несколькими эквивалентными и специализированными формами, а также задавать им начальные (стартовые) значения по умолчанию:

```yukino
class Config {
    // Эквивалентные объявления обычных изменяемых полей
    host: string = "localhost"
    set port: int32 = 8080

    // Поле без стартового значения обнуляется ("" / 0 / false / null)
    label: string

    // Статическое поле класса (стартовый литерал обязателен)
    public static MAX_RETRIES: int32 = 5

    fun get_retries(ref this) -> int32 {
        return this.MAX_RETRIES
    }
}

set cfg = init Config()
println(cfg.host)         // "localhost"
println(cfg.port)         // 8080
println(cfg.MAX_RETRIES)  // 5

// Обычные и set-поля можно менять через rewrite
rewrite cfg.port = 9090

// ОШИБКА E0503: static-поле нельзя мутировать через rewrite
// rewrite cfg.MAX_RETRIES = 10
```

Основные правила объявления и инициализации полей класса:

1. **`field: T` и `set field: T` эквивалентны**: оба варианта объявляют обычное поле экземпляра, доступное для изменения через `rewrite obj.field = ...` (или `rewrite this.field = ...`). Одновременное указание `set` и `static` запрещено.
2. **Начальные значения (`field: T = <литерал>`)**:
   - В качестве стартового значения допускаются **только литералы** (включая унарные `-`, `!`, `~` над литералами). Попытка задать вычисляемое выражение (`x: int32 = 1 + 2`) приводит к ошибке `E0401`.
   - При создании объекта через `init ClassName(...)` поля сначала обнуляются, затем применяются стартовые значения (от предков к наследнику), и уже после этого выполняется тело `init(...)`. Поэтому конструктор `init` может перезаписать нужные стартовые значения.
3. **Статические поля (`static field: T = <литерал>`)**:
   - Инициализатор-литерал для `static`-поля **обязателен** (отсутствие `=` вызывает ошибку парсера / `E0401`).
   - Статические поля не занимают память в каждом экземпляре класса (хранятся как глобальная константа и поддерживают `inline_statics`), наследуются подклассами (доступны через `this.FIELD`, `super.FIELD`, `obj.FIELD`), но **не могут быть изменены** через `rewrite` (`E0503`).

## 3. Свойства: get и set аксессоры

Классы поддерживают вычисляемые свойства с помощью синтаксиса `get` и `set`:

```yukino
class Rectangle {
    w: float64
    h: float64

    fun init(w: float64, h: float64) {
        rewrite this.w = w
        rewrite this.h = h
    }

    // Геттер
    get area() -> float64 {
        return this.w * this.h
    }

    // Сеттер
    set size(val: float64) {
        rewrite this.w = val
        rewrite this.h = val
    }
}

set rect = init Rectangle(10.0, 5.0)
set a: float64 = rect.area // Вызов геттера

// Запись в сеттер требует rewrite
rewrite rect.size = 20.0
```

> [!NOTE]
> Если свойство имеет только `get` (без `set` и без одноименного обычного поля), попытка записи через `rewrite obj.prop = ...` приводит к ошибке компиляции `E0401` (read-only property).

## 4. Перегрузка операторов

Классы могут перегружать операторы через ключевое слово `operator`. Доступны:

- арифметические: `+`, `-`, `*`, `/`, `%`, `**`;
- побитовые операции и сдвиги: `&`, `|`, `^`, `~`, `<<`, `>>`;
- сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`;
- унарные: `!`, `~`, а также унарный минус (метод `operator -` без параметров);
- индексация: `[]` и `[]=`.

Если определен только `==`, компилятор автоматически выводит `!=` как отрицание результата `==`. Диспетчеризация перегруженных операторов реализована для операндов-классов.

```yukino
class Complex {
    re: float64
    im: float64

    fun init(re: float64, im: float64) {
        rewrite this.re = re
        rewrite this.im = im
    }

    operator +(other: Complex) -> Complex {
        return init Complex(this.re + other.re, this.im + other.im)
    }

    operator ==(other: Complex) -> bool {
        return this.re == other.re && this.im == other.im
    }
}

set c1 = init Complex(1.0, 2.0)
set c2 = init Complex(3.0, 4.0)
set c3 = c1 + c2 // Вызывает operator +
```

## 5. Интерфейсы (interface)

Интерфейсы объявляют контракты методов, которые класс обязуется реализовать. Классы декларируют реализацию с помощью ключевого слова `with`:

```yukino
interface Describable {
    fun describe() -> string
}

class Item with Describable {
    title: string

    fun init(title: string) {
        rewrite this.title = title
    }

    fun describe() -> string {
        return this.title
    }
}

fun print_description(d: Describable) {
    println(d.describe())
}
```

> [!NOTE]
> Typechecker гарантирует, что класс, реализующий интерфейс (`with InterfaceName`), содержит все требуемые методы с правильными сигнатурами. При вызове методов через интерфейсную переменную компилятор выполняет динамическую диспетчеризацию через таблицу интерфейсных методов `itable`.

### 5.1 Обобщенные интерфейсы (Generic Interfaces)

Интерфейсы могут объявлять параметры типов (`interface Name<T>` или `interface Name<T, R>`):

```yukino
interface Box<T> {
    fun set_val(v: T) -> int32
    fun get_val() -> T
}

class StringBox with Box<string> {
    item: string

    fun set_val(v: string) -> int32 {
        rewrite this.item = v
        return 0
    }

    fun get_val() -> string {
        return this.item
    }
}

fun print_box(b: Box<string>) {
    println(b.get_val())
}
```

Класс реализует обобщенный интерфейс с указанием конкретных аргументов типов (`with Box<string>`). При вызове методов через интерфейсную переменную компилятор генерирует динамическую диспетчеризацию через `itable` с проверкой типов на этапе компиляции.

## 6. Перечисления (enum)

Перечисления (`enum`) в Yukino представляют собой типы-значения с дискриминированным тегом. Они позволяют задавать закрытый набор возможных состояний и объединять простые числовые метки с богатыми алгебраическими типами данных (ADT / Tagged Unions).

### 6.1 Объявление и разновидности вариантов

Yukino поддерживает три разновидности вариантов внутри перечисления:

1. **Простые варианты (Simple)**:
   Именованные константы без полезной нагрузки. Компилятор автоматически назначает каждому варианту последовательный целочисленный тег, начиная с нуля:

   ```yukino
   enum Color {
       Red,
       Green,
       Blue
   }
   ```

2. **Варианты со значениями (WithValue)**:
   Варианты с явно заданными целочисленными константами. Удобны для кодов протоколов, системных ошибок и битовых флагов:

   ```yukino
   enum HttpStatus {
       Ok = 200,
       Created = 201,
       BadRequest = 400,
       NotFound = 404,
       ServerError = 500
   }
   ```

3. **ADT-варианты с полезной нагрузкой (Adt)**:
   Варианты, несущие типизированные поля данных в круглых скобках. Разные варианты одного перечисления могут содержать разное количество полей различных типов или не содержать их вовсе:

   ```yukino
   enum WebEvent {
       PageLoad,
       KeyPress(key: char),
       Click(x: int64, y: int64),
       Message(text: string)
   }
   ```

### 6.2 Создание и использование значений

Создание экземпляров перечисления выполняется с использованием квалифицированного пути `EnumName::Variant`:

```yukino
// Простые варианты
set c: Color = Color::Red

// Варианты с числовым значением
set status: HttpStatus = HttpStatus::Ok

// Варианты с полезной нагрузкой (ADT)
set ev_load: WebEvent = WebEvent::PageLoad
set ev_key: WebEvent = WebEvent::KeyPress('Q')
set ev_click: WebEvent = WebEvent::Click(100, 200)
set ev_msg: WebEvent = WebEvent::Message("соединение установлено")
```

### 6.3 Сопоставление с образцом в switch

Перечисления наиболее полно раскрываются в сочетании с конструкцией `switch`. В Yukino ветки `switch` не требуют ключевого слова `case` и записываются в виде `Шаблон -> { тело }`.

#### Проверка полноты (Exhaustiveness checking)

Компилятор строго отслеживает полноту сопоставления. Если в `switch` без ветки `else ->` не покрыты все варианты перечисления, компилятор останавливает сборку с ошибкой `E0405`:

```yukino
set color = Color::Green

// Все варианты Color покрыты — проверка проходит успешно
switch color {
    Color::Red -> {
        println("Остановка")
    }
    Color::Green -> {
        println("Движение")
    }
    Color::Blue -> {
        println("Внимание")
    }
}
```

#### Ветка по умолчанию (else ->) и объединение вариантов (|)

Если требуется обработать только подмножество вариантов, оставшиеся можно перехватить через ветку `else ->`. Несколько вариантов с одинаковой логикой объединяются оператором `|`:

```yukino
set status = HttpStatus::NotFound

switch status {
    HttpStatus::Ok | HttpStatus::Created -> {
        println("Успешный статус")
    }
    HttpStatus::NotFound -> {
        println("Ресурс не найден")
    }
    else -> {
        println("Другой код состояния")
    }
}
```

> [!NOTE]
> Любой шаблон, размещенный после ветки `else ->` или шаблона-подстановки `_`, считается недостижимым и приводит к ошибке компиляции `E0406`.

#### Деструктуризация полей полезной нагрузки (ADT)

При сопоставлении вариантов с полезной нагрузкой поля автоматически распаковываются в переменные внутри соответствующей ветки:

```yukino
set event = WebEvent::Click(1024, 768)

switch event {
    WebEvent::PageLoad -> {
        println("Страница полностью загружена")
    }
    WebEvent::KeyPress(k) -> {
        println("Пользователь нажал клавишу: " + cast(k, "string"))
    }
    WebEvent::Click(x, y) -> {
        println("Клик мыши в точке: (${x}, ${y})")
    }
    WebEvent::Message(msg) -> {
        println("Входящее сообщение: " + msg)
    }
}
```

#### Охранные выражения (guards)

К шаблону варианта можно добавить дополнительное логическое условие через ключевое слово `if`:

```yukino
switch event {
    WebEvent::Click(x, y) if x < 0 || y < 0 -> {
        println("Клик за пределами активной области")
    }
    WebEvent::Click(x, y) -> {
        println("Клик в рабочей зоне: (${x}, ${y})")
    }
    else -> {}
}
```

### 6.4 Модель памяти и сравнение

`enum` в Yukino является типом-значением (value type) с разметкой размеченного объединения (tagged union):
- Поле тега дискриминанта (`i32`, 4 байта), определяющее активный вариант.
- Байтовый буфер `[N x i8]` под полезную нагрузку, выровненный по максимальному выравниванию полей. Размер `N` равен максимальному размеру полезной нагрузки среди всех вариантов данного перечисления (для простых перечислений `N = 0`).

Перечисления размещаются непосредственно на стеке или встраиваются в память структур. Экземпляры одного и того же перечисления поддерживают операторы сравнения на равенство `==` и неравенство `!=`:

```yukino
set current_state = Color::Red
set target_state = Color::Green

if current_state == target_state {
    println("Состояния совпадают")
} else if current_state != Color::Blue {
    println("Текущее состояние отличается от Blue")
}
```
