## 1. Официальные расширения

### 1.1 Yukino LSP: Zed

Официальное расширение Yukino для современного редактора Zed.

- Исходный код расширения: [zed-yukino](https://github.com/yukitsuri/zed-yukino)
- Грамматика подсветки синтаксиса: [tree-sitter-yukino](https://github.com/yukitsuri/tree-sitter-yukino)

В редакторе Zed расширения проходят ручную проверку разработчиками через Pull Request в официальный каталог. По этой причине расширение `Yukino LSP` будет довольно долго находиться на модерации. На данный момент установка производится вручную в режиме разработки (Dev Extension).

#### Шаги установки:

1. **Установка языкового сервера `yukino-lsp` через Lacie**

   Языковой сервер обеспечивает работу автодополнения, проверку типов, подсветку ошибок и навигацию по символам. Без установленного LSP порядка 80% возможностей расширения работать не будут.

   - Инструкция по установке пакетного менеджера Lacie: [shareui/lacie install guide](https://github.com/shareui/lacie/tree/main/docs/install)
   - Исходный код языкового сервера: [yukitsuri/yukino-lsp](https://github.com/yukitsuri/yukino-lsp)

   Выполните установку `yukino-lsp`:

   ```sh
   lacie add github:yukitsuri/yukino-lsp
   ```

   Убедитесь, что бинарник `yukino-lsp` доступен в системной переменной `PATH`.

2. **Клонирование репозитория расширения**

   Склонируйте исходный код расширения для Zed:

   ```sh
   git clone https://github.com/yukitsuri/zed-yukino
   ```

3. **Установка в Zed**

   - Запустите редактор Zed.
   - Нажмите комбинацию клавиш `Ctrl + Shift + X` для вызова панели расширений.
   - Нажмите кнопку **Install Dev Extension**.
   - Выберите директорию, в которую был склонирован репозиторий (папку, содержащую файл `extension.toml`).

#### Настройки расширения в Zed:

Расширение для Zed по умолчанию автоматически обнаруживает исполняемый файл `yukino-lsp` в `PATH` и запускает его с подкомандой `lsp`.

Если требуется явно указать путь к бинарнику или передать дополнительные аргументы, добавьте следующую секцию в ваш `settings.json` в Zed:

```json
{
  "lsp": {
    "yukino-lsp": {
      "binary": {
        "path": "/путь/к/yukino-lsp",
        "arguments": ["lsp"]
      }
    }
  }
}
```

### 1.2 Yukino LSP: VSCode

Официальное расширение Yukino для редактора Visual Studio Code.

- Исходный код расширения: [vscode-yukino](https://github.com/yukitsuri/vscode-yukino)

#### Шаги установки:

1. **Установка языкового сервера `yukino-lsp` через Lacie**

   Языковой сервер обеспечивает работу автодополнения, проверку типов, подсветку ошибок и навигацию по символам. Без установленного LSP порядка 80% возможностей расширения работать не будут.

   - Инструкция по установке пакетного менеджера Lacie: [shareui/lacie install guide](https://github.com/shareui/lacie/tree/main/docs/install)
   - Исходный код языкового сервера: [yukitsuri/yukino-lsp](https://github.com/yukitsuri/yukino-lsp)

   Выполните установку `yukino-lsp`:

   ```sh
   lacie add github:yukitsuri/yukino-lsp
   ```

2. **Установка расширения в VS Code**

   - Откройте Visual Studio Code.
   - Перейдите в панель поиска расширений с помощью комбинации клавиш `Ctrl + Shift + X`.
   - Введите в строке поиска: `Yukino LSP`.
   - Нажмите кнопку **Install** («Установить»).

#### Настройки расширения в VS Code:

Параметры расширения настраиваются через графический интерфейс настроек (Раздел *Extensions -> Yukino*) либо напрямую в файле `settings.json`:

- `yukino.server.path` (`string | null`, по умолчанию: `null`)  
  Абсолютный путь к исполняемому файлу `yukino-lsp`. Если значение не задано (`null`), расширение выполняет автоматический поиск в системном `PATH`, каталогах менеджера пакетов Lacie и локальных путях.
- `yukino.server.extraArgs` (`string[]`, по умолчанию: `[]`)  
  Дополнительные аргументы командной строки, передаваемые языковому серверу при старте.
- `yukino.server.trace` (`"off" | "messages" | "verbose"`, по умолчанию: `"off"`)  
  Уровень трассировки взаимодействия по LSP-протоколу для отладки в панели «Вывод» (Output).
- `yukino.codeLens.enable` (`boolean`, по умолчанию: `true`)  
  Включение интерактивных кнопок CodeLens над точками входа (функция `main`) и тестовыми функциями `#[test]`.
- `yukino.inlayHints.enable` (`boolean`, по умолчанию: `true`)  
  Отображение встроенных подсказок (Inlay Hints) для выведенных компилятором типов переменных.

#### Доступные команды в командной палитре (`Ctrl + Shift + P`):

- `Yukino: Restart Language Server` — перезапуск языкового сервера.
- `Yukino: Run (main)` — запуск функции `main` текущего проекта.
- `Yukino: Run Current File` — запуск текущего активного файла.
- `Yukino: Run Test` — запуск теста под курсором.
- `Yukino: Run All Tests` — запуск всех тестов проекта.
- `Yukino: Build Project` — сборка проекта.
- `Yukino: Check Diagnostics` — принудительная перепроверка синтаксиса и ошибок.
- `Yukino: Show Documentation` — открытие документации Yukino.
- `Yukino: Open Status Menu` — контекстное меню действий расширения.

## 2. Справочник команд yukino-lsp

> [!NOTE]
> **Обычным пользователям редакторов изучать и вызывать эти команды вручную не требуется.**  
> Расширения для редакторов (Zed, VS Code) автоматически управляют бинарником `yukino-lsp` и взаимодействуют с ним в фоновом режиме по стандартному протоколу LSP.  
> Данный справочник предназначен для разработчиков интеграций с другими редакторами (например, Neovim, Emacs, Helix), авторов скриптов автоматизации, CI/CD-пайплайнов или ручной отладки.

Утилита `yukino-lsp` объединяет сервер Language Server Protocol и инструменты командной строки для статического анализа и форматирования кода на языке Yukino.

### Команда: `lsp`

Запуск сервера Language Server Protocol через стандартные потоки ввода-вывода (stdio). Это основной режим, используемый редакторами кода.

```sh
yukino-lsp lsp
```

### Команда: `check`

Проверка синтаксиса и вывод диагностических сообщений без запуска интерактивного сервера.

```sh
yukino-lsp check [путь] [--json]
```

- `[путь]` — путь к файлу `.ykn` или директории проекта (по умолчанию: текущий каталог `.`).
- `--json` — вывод результатов проверки в формате JSON (удобно для линтеров и CI/CD).
- Возвращает код `0` при отсутствии ошибок и ненулевой код при наличии диагностических ошибок.

### Команда: `watch`

Непрерывное отслеживание изменений файлов и автоматический перезапуск проверки.

```sh
yukino-lsp watch [путь] [--delay <мс>] [--json]
```

- `[путь]` — целевая директория или файл (по умолчанию: `.`).
- `--delay <мс>` — задержка между повторными проверками в миллисекундах (по умолчанию: 300).
- `--json` — вывод результатов в машиночитаемом формате JSON.

### Команда: `context`

Получение детального контекста символа в заданной позиции исходного кода.

```sh
yukino-lsp context <файл.ykn> --line <строка> --col <колонка>
```

- `--line <строка>` — номер строки (отсчет с 0).
- `--col <колонка>` — номер колонки (отсчет с 0).

### Команда: `doc`

Отображение документации по имени символа (функция, структура, тип).

```sh
yukino-lsp doc <имя_символа> [--json]
```

### Команда: `format`

Форматирование исходного файла Yukino на месте (in-place).

```sh
yukino-lsp format <файл.ykn>
```

### Общие флаги

- `yukino-lsp --version`, `-v`, `version` — вывод версии утилиты.
- `yukino-lsp --help`, `-h`, `help` — вывод краткой справки по доступным командам.
