# Модуль std.hash

Модуль `std.hash` предоставляет комплексный набор алгоритмов вычисления контрольных сумм и криптографических хэш-функций, реализованных полностью на чистом Yukino без сторонних рантайм-зависимостей. Модуль объединяет как высокоскоростные алгоритмы общего назначения, так и общепризнанные международные стандарты безопасности:

- **BitHash64:** некриптографический 64-битный хэш, оптимизированный для максимальной пропускной способности ([исходный репозиторий](https://github.com/shareui/bithash)). Хотя эта хэш-функция не является широко известной, она добавлена в стандартную библиотеку как проект главного разработчика и основателя Yukino, к тому же BitHash отлично показывает себя на практике и часто выручает в прикладных задачах. Алгоритм предназначен для ассоциативных массивов (хэш-таблиц), кэшей в памяти, фильтров Блума и дедупликации данных, где решающее значение имеет производительность на такт процессора и равномерное лавинное распределение бит.
- **SHA-2 (SHA-256, SHA-512):** общепринятый мировой криптографический стандарт (FIPS 180-4, RFC 6234). Необходим для совместимости с существующими протоколами безопасности, проверки TLS-сертификатов, цифровых подписей, блокчейн-структур и корпоративных политик соответствия.
- **SHA-3 (SHA3-256, SHA3-512):** современный криптографический стандарт нового поколения (FIPS 202) на базе перестановочно-губчатой архитектуры Keccak-f[1600]. Обладает принципиально отличным от семейства MD/SHA внутренним устройством, математически невосприимчив к атакам удлинением сообщения (length extension attack) и служит надежной альтернативой классическому SHA-2.
- **BLAKE3:** высокопроизводительный криптографический хэш на базе древовидной структуры Меркла (Merkle tree) и блочной функции сжатия ChaCha. Обеспечивает уровень криптографической стойкости 128 бит (на уровне SHA-256), превосходя традиционные алгоритмы по скорости в несколько раз при хэшировании больших файлов и непрерывных потоков.
- **Вспомогательные криптографические утилиты:** шестнадцатеричное кодирование и декодирование (`bytes_to_hex`, `hex_to_bytes`), сравнение с защитой от атак по времени (`constant_time_eq`, `constant_time_eq_str`, `equal`) и потоковое пофайловое сравнение без полной загрузки в память (`file_eq`).

## 1. Подключение: load std.hash

Импорт всего пакета:

```yukino
load std.hash
```

Это сделает доступными следующие сущности:

- **Структуры ошибок:** `HashError`.
- **Классы потокового хэширования:** `BitHash64`, `Sha256`, `Sha512`, `Sha3_256`, `Sha3_512`, `Blake3`.
- **Функции быстрого хэширования:** `bithash64`, `bithash64_str`, `bithash64_file`, `sha256`, `sha256_str`, `sha256_file`, `sha512`, `sha512_str`, `sha512_file`, `sha3_256`, `sha3_256_str`, `sha3_256_file`, `sha3_512`, `sha3_512_str`, `sha3_512_file`, `blake3`, `blake3_str`, `blake3_file`.
- **Фабрики потоковых классов:** `sha3_256_init`, `sha3_512_init`, `blake3_init`.
- **Вспомогательные утилиты:** `bytes_to_hex`, `hex_to_bytes`, `constant_time_eq`, `constant_time_eq_str`, `equal`, `file_eq`.

Все перечисленные сущности также автоматически становятся доступны при загрузке всей стандартной библиотеки целиком: `load std`.

## 4. Структуры данных и ошибок (паники)

### 4.1 public struct HashError

Структура ошибки, используемая при передаче некорректных входных параметров в функции модуля (например, нечетная длина или недопустимые символы в шестнадцатеричной строке).

```yukino
public struct HashError {
    message: string
    code: int32
}
```

- `message`: строковое описание ошибки.
- `code`: числовой код ошибки:
  - `101`: нечетная длина строки при шестнадцатеричном декодировании.
  - `102`: обнаружен недопустимый шестнадцатеричный символ.

### 6.20 hex_to_bytes

### 6.21 constant_time_eq

Выполняет побайтовое сравнение двух срезов `bytes` за константное время, исключая утечки информации через побочные каналы времени выполнения (timing attacks).

```yukino
public fun constant_time_eq(ref a: bytes, ref b: bytes) -> bool
```

Возвращает логическое значение `true`, если срезы идентичны по длине и содержимому, иначе `false`.

Функция никогда не вызывает панику.

### 6.24 file_eq

Сравнивает контрольные суммы двух файлов на диске по алгоритму BLAKE3 в потоковом режиме, не загружая файлы в оперативную память целиком.

```yukino

```

Возвращает логическое значение `true`, если оба файла существуют и имеют идентичные контрольные суммы, иначе `false`. Если размеры файлов не совпадают, функция мгновенно возвращает `false` без вычисления хэша.

В случае невозможности открытия или чтения файлов вызывает панику со структурой `IoError`.

```yukino
load std.hash.common: file_eq
load std.io: println

fun main() {
    if file_eq("original.iso", "copy.iso") {
        println("Files are byte-for-byte identical")
    }
}
```
