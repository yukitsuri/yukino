# Модуль std.os

Модуль `std.os` предоставляет прямой доступ к системным вызовам операционной системы, функциям libc и платформозависимым интерфейсам (POSIX/Unix, Linux, Windows, Android) без накладных расходов абстракций.

---

## 1. Подключение: load std.os

Импорт всего пакета:

```yukino
// Все платформенные API разом
load std.os

// Либо точечно по необходимым платформам
load std.os.unix
load std.os.linux
load std.os.windows
load std.os.android
```

При импорте в текущую область видимости становятся доступны:

- **Константы:**
  - Сигналы POSIX (`SIGHUP`, `SIGINT`, `SIGQUIT`, `SIGILL`, `SIGTRAP`, `SIGABRT`, `SIGKILL`, `SIGUSR1`, `SIGSEGV`, `SIGUSR2`, `SIGPIPE`, `SIGALRM`, `SIGTERM`, `SIGCHLD`, `SIGCONT`, `SIGSTOP`, `SIGTSTP`);
  - Ожидание Win32 (`INFINITE`, `WAIT_OBJECT_0`, `WAIT_TIMEOUT`);
  - Приоритеты Android logcat (`ANDROID_LOG_UNKNOWN`, `ANDROID_LOG_DEFAULT`, `ANDROID_LOG_VERBOSE`, `ANDROID_LOG_DEBUG`, `ANDROID_LOG_INFO`, `ANDROID_LOG_WARN`, `ANDROID_LOG_ERROR`, `ANDROID_LOG_FATAL`, `ANDROID_LOG_SILENT`).
- **Структуры ошибок:**
  - `OsError` — структура системной ошибки операционной системы.
- **Интерфейсы POSIX/Unix (`std.os.unix`):**
  - `fork`, `execve`, `waitpid`, `getpid`, `getppid`, `kill`, `chmod`, `chown`, `umask`, `getuid`, `geteuid`, `getgid`, `getegid`, `fcntl`.
- **Интерфейсы Linux (`std.os.linux`):**
  - `epoll_create1`, `eventfd`, `timerfd_create`, `memfd_create`, `prctl_set_name`, `prctl_get_name`, `gettid`.
- **Интерфейсы Windows (`std.os.windows`):**
  - `terminate_process`, `get_current_process_id`, `get_process_id`, `close_handle`, `wait_for_single_object`.
- **Интерфейсы Android (`std.os.android`):**
  - `android_log_print`.

Все перечисленные сущности также автоматически становятся доступны при загрузке всей стандартной библиотеки целиком: `load std`.

## 2. Бесконфликтные имена libc и мангалинг

Компилятор Yukino автоматически применяет безопасный мангалинг символов LLVM IR для всех функций `fun` (шаблон `__yukifun_{name}_{args}__{ret}`), что исключает любые коллизии компоновщика с функциями рантайма libc (такими как `fork`, `execve`, `getpid`, `kill`, `fcntl` и др.). В коде Yukino используются стандартные канонические имена системных функций:
- `fork`
- `execve`
- `waitpid`
- `getpid` / `getppid`
- `kill`
- `chmod` / `chown`
- `umask`
- `getuid` / `geteuid` / `getgid` / `getegid`
- `fcntl`
- `epoll_create1`
- `eventfd`
- `timerfd_create`
- `memfd_create`
- `gettid`

## 4. Структуры данных и ошибок (паники)

### 4.1 OsError

Структура системной ошибки операционной системы. В текущей реализации ни одна функция `std.os` не возвращает её и не паникует с ней: все функции модуля сообщают об ошибках через возвращаемые значения (`-1`, `false` или `0`).

```yukino
public struct OsError {
    message: string
    code: int32
}
```

- `message` — текстовое описание ошибки операционной системы.
- `code` — числовой код ошибки `errno` или код ошибки Win32/NTSTATUS.

## 5. Справочник функций: POSIX и Unix (std.os.unix)

#### 5.1 fork

Вызывает системный вызов `fork(2)` для создания нового дочернего процесса путем дублирования текущего.

```yukino
public fun fork() -> int32
```

Возвращает `0` в дочернем процессе, PID дочернего процесса в родительском процессе, либо `-1` при ошибке создания процесса.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: fork
load std.io: println

set pid = fork()
if pid == 0 {
    println("Дочерний процесс")
} else if pid > 0 {
    println("Родительский процесс, дочерний PID: ${pid}")
}
```

### 5.2 execve

Заменяет текущий образ процесса новым исполняемым файлом `path` с аргументами `args` и переменными окружения `envs`.

```yukino
public fun execve(path: string, args: string[], envs: string[]) -> int32
```

При успешном выполнении функция не возвращает управление в текущую программу. При ошибке возвращает целочисленный код `-1`.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: execve
load std.io: println

// execve("/bin/ls", ["ls", "-l"], ["PATH=/bin:/usr/bin"])
```

### 5.3 waitpid

Ожидает смены состояния дочернего процесса `pid` с заданными флагами `options` (например, `1` для флага `WNOHANG`).

```yukino
public fun waitpid(pid: int32, options: int32) -> int32
```

Возвращает PID завершенного дочернего процесса, `0` при использовании `WNOHANG`, если статус еще не изменился, либо `-1` при ошибке системного вызова.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: waitpid
load std.io: println

set res = waitpid(-1, 1)
println("Статус ожидания: ${res}")
```

### 5.4 getpid / getppid

Возвращают идентификатор текущего процесса (PID) и идентификатор родительского процесса (PPID) соответственно через системные вызовы `getpid(2)` и `getppid(2)`.

```yukino
public fun getpid() -> int32
public fun getppid() -> int32
```

Возвращают числовые идентификаторы процессов типа `int32`.

Функции никогда не вызывают панику.

```yukino
load std.os.unix: getpid, getppid
load std.io: println

set pid = getpid()
set ppid = getppid()
println("PID: ${pid}, PPID: ${ppid}")
```

### 5.5 kill

Отправляет системный сигнал с номером `sig` процессу с идентификатором `pid` через системный вызов `kill(2)`.

```yukino
public fun kill(pid: int32, sig: int32) -> int32
```

Возвращает `0` при успешной отправке сигнала либо `-1` в случае ошибки.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: kill, SIGTERM
load std.io: println

set res = kill(1234, SIGTERM)
println("Результат отправки сигнала: ${res}")
```

### 5.6 chmod

Изменяет права доступа к файлу или каталогу по пути `path` на битовую маску `mode` (например, `0o755`).

```yukino
public fun chmod(path: string, mode: uint32) -> int32
```

Возвращает `0` при успешном изменении прав доступа либо `-1` при ошибке.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: chmod
load std.io: println

set res = chmod("script.sh", 493) // 0o755
println("chmod результат: ${res}")
```

### 5.7 chown

Изменяет владельца (`uid`) и группу (`gid`) указанного файла или каталога по пути `path`.

```yukino
public fun chown(path: string, uid: uint32, gid: uint32) -> int32
```

Возвращает `0` при успешной смене владельца либо `-1` при ошибке.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: chown
load std.io: println

set res = chown("data.bin", 1000, 1000)
println("chown результат: ${res}")
```

### 5.8 umask

Устанавливает маску создания файлов текущего процесса на значение `mask`.

```yukino
public fun umask(mask: uint32) -> uint32
```

Возвращает предыдущее значение маски создания файлов типа `uint32`.

Функция никогда не вызывает панику.

```yukino
load std.os.unix: umask
load std.io: println

set old_mask = umask(18) // 0o022
println("Предыдущая маска umask: ${old_mask}")
```

### 5.9 getuid / geteuid / getgid / getegid

Возвращают реальный идентификатор пользователя (UID), эффективный идентификатор пользователя (EUID), реальный идентификатор группы (GID) и эффективный идентификатор группы (EGID) процесса соответственно.

```yukino
public fun getuid() -> uint32
public fun geteuid() -> uint32
public fun getgid() -> uint32
public fun getegid() -> uint32
```

Возвращают числовые идентификаторы пользователя или группы типа `uint32`.

Функции никогда не вызывают панику.

```yukino
load std.os.unix: getuid, geteuid, getgid, getegid
load std.io: println

set uid = getuid()
set gid = getgid()
println("UID: ${uid}, GID: ${gid}")
```

### 5.10 fcntl

Выполняет низкоуровневую операцию управления файловым дескриптором `fd` с командой `cmd` и дополнительным аргументом `arg` (`fcntl(2)`).

```yukino
public fun fcntl(fd: int32, cmd: int32, arg: int32) -> int32
```

Возвращает результат системного вызова (неотрицательное число при успехе или `-1` при ошибке).

Функция никогда не вызывает панику.

```yukino
load std.os.unix: fcntl
load std.io: println

set flags = fcntl(0, 3, 0) // F_GETFL = 3
println("Флаги stdin: ${flags}")
```

## 6. Справочник функций: Linux (std.os.linux)

### 6.1 epoll_create1

Создает новый экземпляр подсистемы мультиплексирования epoll с переданными флагами `flags` (например, `0` или `EPOLL_CLOEXEC` = 0x80000).

```yukino
public fun epoll_create1(flags: int32) -> int32
```

Возвращает файловый дескриптор epoll типа `int32` либо `-1` при возникновении системной ошибки.

Функция никогда не вызывает панику.

```yukino
load std.os.linux: epoll_create1
load std.io: println

set epfd = epoll_create1(0)
println("epoll дескриптор: ${epfd}")
```

### 6.2 eventfd

Создает файловый дескриптор `eventfd` для межпроцессного или межпоточного уведомления о событиях со стартовым счетчиком `initval` и флагами `flags`.

```yukino
public fun eventfd(initval: uint32, flags: int32) -> int32
```

Возвращает дескриптор события типа `int32` либо `-1` при ошибке.

Функция никогда не вызывает панику.

```yukino
load std.os.linux: eventfd
load std.io: println

set efd = eventfd(0, 0)
println("eventfd дескриптор: ${efd}")
```

### 6.3 timerfd_create

Создает дескриптор таймера `timerfd` с использованием указанных часов `clockid` (например, `0` для `CLOCK_REALTIME` или `1` для `CLOCK_MONOTONIC`) и флагов `flags`.

```yukino
public fun timerfd_create(clockid: int32, flags: int32) -> int32
```

Возвращает дескриптор таймера типа `int32` либо `-1` при сбое создания.

Функция никогда не вызывает панику.

```yukino
load std.os.linux: timerfd_create
load std.io: println

set tfd = timerfd_create(1, 0) // CLOCK_MONOTONIC
println("timerfd дескриптор: ${tfd}")
```

### 6.4 memfd_create

Создает анонимный дескриптор файла в оперативной памяти Linux с именем `name` и флагами `flags`.

```yukino
public fun memfd_create(name: string, flags: uint32) -> int32
```

Возвращает дескриптор файла в памяти типа `int32` либо `-1` при ошибке создания.

Функция никогда не вызывает панику.

```yukino
load std.os.linux: memfd_create
load std.io: println

set mfd = memfd_create("shared_buf", 0)
println("memfd дескриптор: ${mfd}")
```

### 6.5 prctl_set_name / prctl_get_name

Устанавливает и считывает системное имя текущего потока или процесса (до 16 байт) через системный вызов ядра `prctl(PR_SET_NAME)`.

```yukino
public fun prctl_set_name(name: string) -> int32
public fun prctl_get_name() -> string
```

`prctl_set_name` возвращает `0` при успехе или `-1` при ошибке. `prctl_get_name` возвращает строковое имя текущего потока.

Функции никогда не вызывают панику.

```yukino
load std.os.linux: prctl_set_name, prctl_get_name
load std.io: println

prctl_set_name("worker-01")
set name = prctl_get_name()
println("Имя потока: " + name)
```

### 6.6 gettid

Возвращает идентификатор потока ядра Linux (TID, Thread ID) вызывающего потока через вызов `gettid(2)`.

```yukino
public fun gettid() -> int32
```

Возвращает целочисленный идентификатор потока типа `int32`.

Функция никогда не вызывает панику.

```yukino
load std.os.linux: gettid
load std.io: println

set tid = gettid()
println("TID потока ядра: ${tid}")
```

## 7. Справочник функций: Windows (std.os.windows)

### 7.1 terminate_process

Принудительно завершает процесс, идентифицируемый дескриптором `handle`, с кодом выхода `exit_code` через системный вызов Windows API `TerminateProcess`.

```yukino
public fun terminate_process(handle: int64, exit_code: uint32) -> bool
```

Возвращает `true` в случае успешного завершения процесса, иначе `false`.

Функция никогда не вызывает панику.

```yukino
load std.os.windows: terminate_process
load std.io: println

// terminate_process(proc_handle, 1)
```

### 7.2 get_current_process_id

Возвращает системный идентификатор текущего процесса в операционной системе Windows (`GetCurrentProcessId`).

```yukino
public fun get_current_process_id() -> uint32
```

Возвращает беззнаковый 32-битный идентификатор процесса типа `uint32`.

Функция никогда не вызывает панику.

```yukino
load std.os.windows: get_current_process_id
load std.io: println

set pid = get_current_process_id()
println("Win32 PID: ${pid}")
```

### 7.3 get_process_id

Возвращает системный идентификатор процесса (PID) по открытому дескриптору `handle` (`GetProcessId`).

```yukino
public fun get_process_id(handle: int64) -> uint32
```

Возвращает PID процесса типа `uint32` либо `0` в случае недействительного дескриптора или ошибки.

Функция никогда не вызывает панику.

```yukino
load std.os.windows: get_process_id
load std.io: println

// set pid = get_process_id(proc_handle)
```

### 7.4 close_handle

Закрывает открытый дескриптор объекта Win32 `handle` через вызов `CloseHandle`.

```yukino
public fun close_handle(handle: int64) -> bool
```

Возвращает `true` в случае успешного закрытия дескриптора, иначе `false`.

Функция никогда не вызывает панику.

```yukino
load std.os.windows: close_handle
load std.io: println

// close_handle(handle)
```

### 7.5 wait_for_single_object

Ожидает перехода указанного объекта `handle` в сигнальное состояние с таймаутом `timeout_ms` в миллисекундах (`WaitForSingleObject`).

```yukino
public fun wait_for_single_object(handle: int64, timeout_ms: uint32) -> uint32
```

Возвращает код результата ожидания (`WAIT_OBJECT_0`, `WAIT_TIMEOUT` или код сбоя).

Функция никогда не вызывает панику.

```yukino
load std.os.windows: wait_for_single_object, WAIT_OBJECT_0
load std.io: println

// set res = wait_for_single_object(handle, 1000)
// if res == WAIT_OBJECT_0 { println("Объект готов") }
```

## 8. Справочник функций: Android (std.os.android)

### 8.1 android_log_print

Выводит форматированное сообщение `text` с тегом `tag` и уровнем приоритета `prio` в системный кольцевой журнал Android logcat через NDK-функцию `__android_log_print`.

```yukino
public fun android_log_print(prio: int32, tag: string, text: string) -> int32
```

Возвращает число записанных байт либо отрицательное значение при ошибке вывода в журнал.

Функция никогда не вызывает панику.

```yukino
load std.os.android: android_log_print, ANDROID_LOG_INFO
load std.io: println

set written = android_log_print(ANDROID_LOG_INFO, "MyApp", "Yukino runtime initialized")
println("Записано в logcat: ${written}")
```
