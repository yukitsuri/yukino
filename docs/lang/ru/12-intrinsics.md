# Встроенные функции компилятора (Intrinsics)

Встроенные функции компилятора (интринсики) — это функции, которые реализуются непосредственно кодогенератором LLVM и рантаймом Yukino, а не кодом стандартной библиотеки. Они доступны глобально в любой части программы без использования директивы `load`.

> [!NOTE]
> Все интринсики компилятора могут вызываться как напрямую по имени (`cast(...)`, `exit(...)`, `typeof!(...)`), так и через опциональный префикс встроенного пространства имен `rt::` (`rt::cast(...)`, `rt::exit(...)`, `rt::typeof!(...)`). Использование `rt::` позволяет избежать конфликтов с пользовательскими функциями.

## 1. Интроспекция типов: typeof!

### 1.1 Сигнатура и назначение

```yukino
typeof!(expr: T) -> string
```

- **Применимо к:** выражениям любого типа `T` (примитивы, составные типы, структуры, срезы, функции и указатели).
- **Возвращаемый тип:** `string` — каноническое строковое имя типа (например, `"int32"`, `"float64"`, `"string"`, `"int32[]"`, `"ptr<char>"`).

Макрос `typeof!(expr)` вычисляется целиком на этапе компиляции. Компилятор определяет статический тип выражения `expr` и подставляет строковый литерал с его описанием. Все сгенерированные строки типов дедуплицируются в секции `rodata` бинарного файла, поэтому накладные расходы при вызове `typeof!` нулевые.

```yukino
set count = 42
set count_type = typeof!(count)       // "int32"

set ratio = 3.14
set ratio_type = typeof!(ratio)       // "float64"

set items = [1, 2, 3]
set items_type = typeof!(items)       // "int32[]"
```

### 1.2 Использование typeof! в операциях приведения

`typeof!` может передаваться в качестве второго аргумента во встроенную функцию `cast`, позволяя привести значение к типу существующей переменной без дублирования имени типа вручную:

```yukino
set sample: int32 = 0
set big_num: int64 = 1000

// Приводит big_num к типу переменной sample (int32)
set matched_val = cast(big_num, typeof!(sample))
```

## 2. Приведение типов: cast

В Yukino отсутствуют неявные преобразования типов: компилятор никогда автоматически не расширяет и не сужает числа, не приводит указатели к адресам и не выполняет автопарсинг строк. Любое явное преобразование выполняется через интринсик `cast`.

### 2.1 Сигнатура и синтаксис вызова

```yukino
cast(value: T, target: "target_type" | typeof!(expr)) -> U
```

- **Параметр 1 (`value`):** исходное значение типа `T`.
- **Параметр 2 (`target`):** целевой тип `U`. Вторым аргументом **обязан** быть либо строковый литерал с именем типа в кавычках (например, `"int32"`, `"uint8"`, `"ptr<char>"`), либо вызов `typeof!(...)`. Передача динамической строковой переменной запрещена и прерывает компиляцию ошибкой `E0431`.
- **Возвращаемый тип:** приведенное значение целевого типа `U`.

> [!NOTE]
> Существует также альтернативный синтаксис с угловыми скобками: `cast<T>(value)` (упоминается в документе [Базовый синтаксис](3-basics.md)). Он выполняет прямое LLVM-приведение значения к целевому типу на уровне битов и **не** проходит через полную матрицу преобразований `cast` из этого раздела: рантайм-функции (форматирование чисел, парсинг строк, паники) для него не вызываются. Для безопасных преобразований со строками и проверками используйте форму `cast(value, "type")`.

### 2.2 Матрица допустимых преобразований

| :--- | :--- | :--- |
| `T` | `T` (тождественный) | Возврат значения без изменений (no-op). |
| `int8..int64`, `uint8..uint64` | `int8..int64`, `uint8..uint64` | Знаковое (`sext`) или беззнаковое (`zext`) расширение, либо усечение битов (`trunc`). Для литералов проверяется диапазон при компиляции. |
| `float32`, `float64` | `float32`, `float64` | Изменение точности с плавающей точкой (`fpext` / `fptrunc`). |
| `int*`, `uint*` | `float32`, `float64` | Преобразование целого в число с плавающей точкой (`sitofp` / `uitofp`). |
| `float32`, `float64` | `int*`, `uint*` | Отбрасывание дробной части (`fptosi` / `fptoui`). |

| `int*`, `uint*` | `char` | Преобразование целочисленной кодовой точки в символ. |

| `string` | `char` | Извлечение первого символа строки. |
| Любое число (`int*`, `uint*`, `float*`) | `string` | Форматирование числа в строковое представление в текущем регионе памяти. |
| `string` | Любое число (`int*`, `uint*`, `float*`) | Парсинг строки в числовое значение соответствующего типа. Пробельные символы по краям строки автоматически обрезаются. |
| `bool` | `int*`, `uint*` | Преобразование булева значения в число (`false -> 0`, `true -> 1`). |

| `ptr<T>`, `cfun(...)`, `null` | `ptr<U>`, `cfun(...)` | Приведение между сырыми указателями и указателями на C-функции. |
| `ptr<T>`, `cfun(...)` | `uint64`, `int64` | Преобразование указателя в целочисленный адрес памяти (`ptrtoint`). |

| `ptr<T>`, `cfun(...)` | `float64` | Преобразование адреса указателя в вещественное число и обратно. |
| `ptr<T>`, `cfun(...)` | `string` | Форматирование адреса указателя в шестнадцатеричную строку. |
| `string` | `ptr<T>`, `cfun(...)` | Парсинг строкового адреса памяти в сырой указатель. |
| `bytes` | `string` | Интерпретация байтового среза как строки без копирования буфера. |
| `string` | `bytes` | Интерпретация строки как байтового среза без копирования буфера. |
| `bool` | `string` | Форматирование булева значения в строку (`"true"` или `"false"`). |
| `string` | `bool` | Парсинг строки в булево значение (`"true"`/`"1"` -> `true`, `"false"`/`"0"` -> `false`). |
| `string` | `char[]` | Преобразование строки в срез символов Unicode (`char[]`) с аллокацией в текущем регионе памяти. |

### 2.3 Числовые преобразования (Numeric <-> Numeric)

Поддерживается преобразование между любыми парами встроенных числовых типов Yukino (`int8`, `int16`, `int32`, `int64`, `uint8`, `uint16`, `uint32`, `uint64`, `float32`, `float64`):

```yukino
set a: int64 = 1024

// Изменение разрядности целых чисел
set b: int32 = cast(a, "int32")
set c: uint8 = cast(a, "uint8")

// Преобразование целых чисел и чисел с плавающей точкой
set pi: float64 = 3.14159
set pi_int: int32 = cast(pi, "int32") // 3 (дробная часть отброшена)
set back_to_float: float32 = cast(pi_int, "float32") // 3.0
```

### 2.4 Преобразования символов (char)

Тип `char` представляет Unicode-символ. `cast` позволяет свободно преобразовывать его в числовой код и строку:

```yukino
set ch: char = 'A'

// Символ в целочисленный код
set code: int32 = cast(ch, "int32") // 65

// Целочисленный код в символ
set ch_restored: char = cast(66, "char") // 'B'

// Символ в строку
set str_val: string = cast(ch, "string") // "A"

// Строка в первый символ
set first_char: char = cast("Yukino", "char") // 'Y'

// Строка в срез символов Unicode (char[])
set letters: char[] = cast("Yukino", "char[]")

// Срез символов Unicode обратно в строку
set reconstructed: string = cast(letters, "string") // "Yukino"
```

### 2.5 Числа и строки (Numeric <-> string)

Приведение числа к строке автоматически форматирует его значение и аллоцирует результат в активном регионе памяти. Обратное приведение выполняет парсинг:

```yukino
// Форматирование числа в строку
set score: int32 = 4200
set text: string = cast(score, "string") // "4200"

// Парсинг строки в число
set parsed_int: int32 = cast("12345", "int32")
set parsed_float: float64 = cast("3.1415", "float64")
```

### 2.6 Логический тип (bool)

Булевы значения преобразуются в целые числа и обратно:

```yukino
set is_active: bool = true

// bool в целое число (0 или 1)
set flag_num: int32 = cast(is_active, "int32") // 1

// Целое число в bool (0 -> false, любое ненулевое -> true)
set flag_bool: bool = cast(0, "bool") // false
set flag_non_zero: bool = cast(42, "bool") // true

// bool в строку ("true" или "false")
set str_true: string = cast(true, "string") // "true"
set str_false: string = cast(false, "string") // "false"

// Строка в bool ("true"/"1" -> true, "false"/"0" -> false)
set b1: bool = cast("true", "bool") // true
set b2: bool = cast("false", "bool") // false
set b3: bool = cast("1", "bool") // true
set b4: bool = cast("0", "bool") // false
```

Приведение строки к `bool` распознает значения `"true"` и `"1"` как `true`, а `"false"` и `"0"` как `false` (пробелы по краям строки автоматически обрезаются). Если строка пустая или указатель равен `null`, возвращается `false`. При передаче некорректного формата строки возникает нетипизированная паника `invalid boolean syntax in string cast to bool`.

### 2.7 Сырые указатели и функции (ptr, cfun, null)

Для взаимодействия с системным C ABI, FFI и низкоуровневой работы с памятью `cast` поддерживает конвертацию указателей и адресов:

```yukino
set value: int64 = 100
set p_val = ptr_of(value) // ptr<int64>

// Приведение между различными типами указателей
set p_bytes: ptr<uint8> = cast(p_val, "ptr<uint8>")

// Получение числового адреса в памяти
set address: uint64 = cast(p_val, "uint64")

// Восстановление указателя из числового адреса
set p_restored: ptr<int64> = cast(address, "ptr<int64>")

// Строка в C-указатель и форматирование адреса в шестнадцатеричную строку
set msg = "Buffer\0"
set c_ptr: ptr<char> = cast(msg, "ptr<char>")
set addr_text: string = cast(c_ptr, "string") // например "0x7f3a10"
```

### 2.8 Байты и строки (bytes <-> string)

Тип `bytes` (байтовый срез `[]uint8`) и тип `string` имеют совместимые структуры дескрипторов буфера. `cast` выполняет быструю интерпретацию памяти без дополнительного выделения и копирования:

```yukino
set original = "hello payload"

// Представление строки как байтового среза
set raw_bytes: bytes = cast(original, "bytes")

// Интерпретация байтового среза обратно в строку
set restored_text: string = cast(raw_bytes, "string")
```

### 2.9 Статическая валидация констант и диагностика ошибок

Компилятор строго верифицирует аргументы `cast` на этапе статического анализа:

1. **Неконстантный целевой тип (`E0431`):** целевой тип обязан быть строковым литералом или `typeof!(...)`.
2. **Несовместимая пара типов (`E0430`):** попытка привести несовместимые структуры (например, структуру к `int32` или срез к числу) вызывает ошибку времени компиляции `invalid type cast from 'T' to 'U'`.
3. **Переполнение константных литералов (`E0430`):** при попытке сузить числовой литерал, не помещающийся в разрядность целевого типа, компилятор останавливает сборку:

```yukino
// Ошибка компиляции E0430: value `1000` exceeds 8 bits for target type `uint8`
set bad = cast(1000, "uint8")
```

### 2.10 Возврат null и паники в функции cast

Поведение `cast` при обработке некорректных или граничных значений строго регламентировано:

#### Когда cast возвращает null
При приведении к типам сырых указателей (`ptr<T>`) или указателей на C-функции (`cfun(...)`):
- `cast(0, "ptr<T>")` возвращает нулевой указатель `null`.
- `cast(null, "ptr<T>")` возвращает `null`.
- `cast("", "ptr<T>")` возвращает `null`.
- `cast("invalid_hex", "ptr<T>")`: если строка не является корректным шестнадцатеричным адресом памяти (например, не парсится шестнадцатеричное число), функция возвращает `null`.

#### Когда cast вызывает panic
Если значение не может быть корректно преобразовано в запрашиваемый тип, рантайм Yukino выбрасывает **нетипизированную панику**: исключение получает вид `"Panic"` без числового кода, а сообщение описывает причину сбоя. Типизированная структура `StringParseError` при ошибках `cast` не используется — она применяется только функциями модуля `std.strings`.

| Преобразование | Условие вызова panic | Сообщение паники |
| :--- | :--- | :--- |
| `string -> char` | Строка пустая (`""`) или `null` | `cannot cast empty or null string to char` |
| `string -> char` | Строка содержит невалидный UTF-8 | `invalid utf-8 in string cast to char` |
| `string -> int*` | Строка пустая (`""`) или `null` | `cannot cast empty or null string to int64` |
| `string -> int*` | Некорректный синтаксис целого числа (буквы, спецсимволы, переполнение) | `invalid integer syntax in string cast to int64` |
| `string -> uint*` | Строка пустая (`""`) или `null` | `cannot cast empty or null string to uint64` |
| `string -> uint*` | Отрицательное число или некорректный синтаксис | `invalid integer syntax in string cast to uint64` |
| `string -> float*` | Строка пустая (`""`) или `null` | `cannot cast empty or null string to float64` |
| `string -> float*` | Некорректный синтаксис вещественного числа | `invalid float syntax in string cast to float64` |

```yukino
// Пример перехвата ошибки невалидного парсинга через sus/catch:
sus {
    set num: int32 = cast("not_a_number", "int32")
} catch {
    println("Ошибка приведения: " + errkind)
}
```

## 3. Аргументы командной строки: args и raw_args

### 3.1 Список аргументов: args

```yukino
args() -> string[]
```

- **Применимо к:** вызывается без аргументов `()`.
- **Возвращаемый тип:** `string[]` — срез строк, содержащий пользовательские аргументы командной строки процесса (аргумент с индексом 0, имя исполняемого файла, автоматически отсекается).

```yukino
fun main() {
    set cli_args = args()
    set total: int64 = cli_args.len()
    
    for i in 0..cli_args.len() {
        set arg_val = cli_args[i]
        // Обработка параметров
    }
}
```

### 3.2 Сырая строка аргументов платформы: raw_args

```yukino
raw_args() -> string
```

- **Применимо к:** вызывается без аргументов `()`.
- **Возвращаемый тип:** `string` — непрерывная строка системных аргументов процесса для прямого взаимодействия с платформенными API и C ABI.

### 3.3 Поведение при ошибках: args и raw_args

- **Возврат null:** функции `args()` и `raw_args()` **никогда не возвращают null** и **никогда не паникуют**.
  - Если процесс запущен без аргументов, `args()` возвращает валидный пустой срез `string[]` нулевой длины (`args().len() == 0`).
  - `raw_args()` возвращает валидную пустую строку `""` нулевой длины.
  - При отсутствии активного региона памяти функции также возвращают пустой срез или пустую строку вместо паники.
- `raw_args()` объединяет пользовательские аргументы процесса в одну строку, разделяя их одиночными пробелами.

## 4. Управление процессом и обработка ошибок

### 4.1 Завершение процесса: exit

```yukino
exit(code: int32) -> never
```

- **Параметр (`code`):** строго целочисленный код возврата типа `int32`.
- **Возвращаемый тип:** `never` — функция не возвращает управление в точку вызова.

```yukino
if critical_config_missing {
    exit(1)
}

// Успешный выход
exit(0)
```

### 4.2 Аварийная остановка: panic и правила обработки ошибок

```yukino
panic(payload: S) -> never
```

- **Параметр:** пользовательская структура ошибки `S` (первое строковое поле структуры с сообщением об ошибке извлекается рантаймом для вывода в консоль).
- **Возвращаемый тип:** `never` — немедленно инициирует аварийное завершение процесса или раскрутку стека в соответствии со стратегией `panic_strategy` в `yuki.toml`.

#### Правила обработки ошибок в проекте:

1. **Отсутствие внешнего значения:** если логика корректна, но значение отсутствует извне (например, ключ в JSON или опциональный параметр) — функция возвращает `null`.
2. **Ошибка времени выполнения:** выбрасывается `panic`. В Yukino компилятор строго требует передачу структуры ошибки в `panic(...)` (передача строк или чисел запрещена). Всегда создается типизированная структура ошибки с полями контекста, чтобы вызывающий код мог перехватывать ее через блок `catch`:
3. **Статус завершения:** если функция по логике ничего не возвращает, возвращается булево значение (`bool`) `true`/`false`, чтобы вызывающий код мог понять результат работы.

```yukino
// 1. Попытка передачи сырой строки отклоняется компилятором на этапе типизации:
// panic("division by zero attempted") // Ошибка компиляции

// 2. Структура ошибки с типизированным контекстом (ПРАВИЛЬНО)
struct MathError {
    message: string
    code: int32
}

if divisor == 0 {
    panic(MathError {
        message: "division by zero attempted",
        code: 101,
    })
}
```

> [!TIP]
> Подробное руководство по обработке ошибок, работе с переменной `errkind`, формам перехвата `catch TempName: Struct`, `catch Struct`, `catch` и лучшим практикам создания типов ошибок приведено в документе: **[14. Обработка ошибок и исключения](14-errors.md)**.


### 4.3 Встроенные проверки: assert, assert_eq, assert_ne

```yukino
assert(condition: bool, [message: string]) -> void
assert_eq(actual: T, expected: T, [message: string]) -> void
assert_ne(actual: T, expected: T, [message: string]) -> void
```

- **Параметры:**
  - `assert`: условие `condition: bool` и опциональное сообщение `message: string`. В текущей реализации компилятор проверяет только условие: сообщение `message` при генерации кода не используется.
  - `assert_eq` / `assert_ne`: значения `actual` и `expected`. Сравнение выполняется только для целочисленных значений; значения других типов не сравниваются, и проверка автоматически считается пройденной. Опциональное сообщение `message` также игнорируется.
- **Возвращаемый тип:** `void`.
- **Поведение при нарушении:** при проваленной проверке рантайм выбрасывает **нетипизированную панику** (вид `"Panic"`, без числового кода) с пустым сообщением. Специальная структура паники для проверок в текущей реализации компилятора не определена.

```yukino
set balance = 100

// Базовая проверка булева условия (при нарушении вызывает нетипизированную панику)
assert(balance > 0)

// Проверка на равенство целочисленных значений
assert_eq(balance, 100)

// Проверка на неравенство
assert_ne(balance, 0)
```

## 5. Работа с низкоуровневой памятью

### 5.1 Оператор ptr_of

```yukino
ptr_of(variable: T) -> ptr<T>
```

- **Параметр (`variable`):** идентификатор локальной переменной (lvalue) любого типа `T`.
- **Возвращаемый тип:** типизированный сырой указатель `ptr<T>`.

```yukino
set counter = 42
set p_counter: ptr<int32> = ptr_of(counter)
```

### 5.2 Конструирование из сырых частей: from_raw_parts

```yukino
// 1. Конструирование строки из указателя на байты и длины (2 аргумента)
string::from_raw_parts(raw_ptr: ptr<uint8>, length: int64 | int32) -> string

// 2. Конструирование среза из указателя, длины и емкости (3 аргумента)
slice::from_raw_parts(raw_ptr: ptr<T>, length: int64 | int32, capacity: int64 | int32) -> T[]
```

- **Параметры:**
  - `string::from_raw_parts` принимает указатель на начало байтового массива `ptr<uint8>` и целое число длины.
  - `slice::from_raw_parts` принимает сырой указатель `ptr<T>` на произвольный тип элементов `T`, длину и емкость. Емкость обязательна: вызов с двумя аргументами всегда конструирует строку, а не срез.
- Обе функции не выполняют валидацию переданных значений: дескриптор создается напрямую из указателя, длины и емкости. Встроенной функции `from_utf8` в компиляторе нет — проверку корректности UTF-8 выполняют функции стандартной библиотеки.

```yukino
// Воссоздание строки из внешнего буфера
set text = string::from_raw_parts(raw_ptr, length)

// Воссоздание среза из сырого буфера
set slice_view = slice::from_raw_parts(raw_items_ptr, 10, 16)
```

### 5.3 Возврат null и поведение при ошибках

- **`string::from_raw_parts(raw_ptr, length)`**:
  - Передача `raw_ptr == null` с нулевой длиной порождает корректный дескриптор пустой строки `{ ptr: null, len: 0 }`.
  - Передача `raw_ptr == null` с ненулевой длиной `length > 0` порождает поврежденный дескриптор; любая последующая операция чтения или индексации приводит к неопределенному поведению.
  - Функция никогда не паникует и не выполняет проверок.

- **`slice::from_raw_parts(raw_ptr, length, capacity)`**:
  - Аналогично конструирует дескриптор среза без валидации: проверка `capacity < length` и корректность указателя не контролируются, функция никогда не паникует.

## 6. Встроенные методы срезов, массивов, строк и байтов

Компилятор предоставляет набор встроенных методов для типов коллекций (`T[]`, `[N]T`), строк (`string`) и байтовых срезов (`bytes`).

| Метод | Допустимые типы получателя | Возвращаемый тип | Описание |
| :--- | :--- | :--- | :--- |
| `.len()` | `string`, `bytes`, `T[]`, `[N]T` | `int64` | Длина строки/байтов в байтах, либо количество элементов в срезе или массиве |
| `.cap()` | `bytes`, `T[]` | `int64` | Текущая выделенная емкость (capacity) среза или байтового буфера |
| `.is_empty()` | `string`, `bytes`, `T[]` | `bool` | Проверка отсутствия элементов (`.len() == 0`) |
| `.as_ptr()` | `string`, `bytes`, `T[]` | `ptr<uint8>` (для string/bytes), `ptr<T>` (для срезов) | Сырой указатель на непрерывный буфер элементов в памяти |
| `.push(elem)` | `T[]`, `bytes` | `void` | Добавление элемента в конец среза с динамическим расширением capacity в регионе |
| `.pop()` | `T[]`, `bytes` | `T?` (для `bytes` — `uint8?`) | Извлечение и удаление последнего элемента среза (возвращает `null`, если срез пуст) |
| `.del(index)` | `T[]`, `bytes` | `void` | Удаление элемента по индексу со сдвигом последующих элементов влево |
| `.clear()` | `T[]`, `bytes` | `void` | Сброс длины среза в 0 (`len = 0`) без освобождения буфера |
| `.reserve(additional)` | `T[]`, `bytes` | `void` | Предварительное резервирование дополнительной емкости в активном регионе памяти |
| `.cp()` | `T[]` | `T[]` | Глубокое копирование (clone) элементов среза в текущий регион памяти |

Пример использования:

```yukino
set buffer: int64[] = [10, 20, 30]

set length: int64 = buffer.len()     // 3
set capacity: int64 = buffer.cap()   // 3 или более
set empty: bool = buffer.is_empty()  // false
set raw_ptr: ptr<int64> = buffer.as_ptr()

// Динамическое добавление элементов в срез
buffer.push(40)
buffer.push(50)

// Извлечение последнего элемента с возвратом nullable
set popped = buffer.pop() // popped: int64? (равен 50)
if popped != null {
    println("Извлечен элемент: " + cast(popped ?? 0, "string"))
}

// Удаление элемента по индексу со сдвигом элементов
buffer.del(1) // удаляет элемент со значением 20

// Предварительное резервирование емкости под новые элементы
buffer.reserve(50)

// Сброс длины среза в 0
buffer.clear()
assert(buffer.is_empty())

// Клонирование среза
set numbers = [1, 2, 3]
set numbers_copy = numbers.cp()

// Длина строки в байтах, проверка пустоты и указатель на байты
set greeting = "Yukino"
set greeting_len: int64 = greeting.len()
set greeting_empty: bool = greeting.is_empty() // false
set greeting_ptr: ptr<uint8> = greeting.as_ptr()
```

### 6.2 Безопасность методов, возврат null и паники

- **Метод `.as_ptr()`**:
  - **Возврат null:** возвращает `null` (`nullptr`), если срез или строка пустые (`.len() == 0`) либо не содержат выделенного буфера.
  - **Паника:** никогда не паникует.

- **Методы `.len()` и `.cap()`**:
  - **Возврат null:** возвращают числовое значение `int64` (`0` для пустых или нулевых структур). Никогда не возвращают `null`.
  - **Паника:** никогда не паникуют.

- **Метод `.is_empty()`**:
  - **Возврат null:** никогда не возвращает `null` (всегда возвращает `bool`).
  - **Паника:** никогда не паникует.

- **Метод `.push(elem)`**:
  - **Возврат null:** не возвращает значение (`void`).
  - **Паника:** никогда не паникует. При невозможности выделить память под расширение буфера (исчерпание региона) элемент молча не добавляется.

- **Метод `.pop()`**:
  - **Возврат null:** возвращает `null`, если срез пуст (`.len() == 0`). При непустом срезе возвращает последнее значение `T` и уменьшает `len` на 1.
  - **Паника:** никогда не паникует.

- **Метод `.del(index)`**:
  - **Возврат null:** не возвращает значение (`void`).
  - **Паника:** при выходе индекса за пределы (`index >= collection.len()`) рантайм выбрасывает **нетипизированную панику** (вид `"Panic"`, без числового кода) с сообщением `slice index out of bounds in slice.del`.

- **Метод `.clear()`**:
  - **Возврат null:** не возвращает значение (`void`).
  - **Паника:** никогда не паникует.

- **Метод `.reserve(additional)`**:
  - **Возврат null:** не возвращает значение (`void`).
  - **Паника:** никогда не паникует. При невозможности зарезервировать дополнительную память резервирование молча пропускается.

- **Метод `.cp()`**:
  - Создает глубокую копию среза в активном регионе памяти. Требует активного региона: при его отсутствии компиляция прерывается ошибкой `array cloning requires an active region`.

- **Операции индексации и срезов (`collection[i]`, `collection[start..end]`):**
  - Индексация и взятие поддиапазона компилируются **без проверки границ**: выход индекса за пределы `0..len-1` или нарушение диапазона `0 <= start <= end <= len` не вызывает панику и приводит к неопределенному поведению (чтение произвольной памяти).
  - Для проверяемого доступа используйте функции стандартной библиотеки: `std.strings.byte_at` и `std.strings.char_at` (вызывают типизированную панику `StringIndexError` при выходе за границы), а `std.strings.slice` и `std.strings.substring` безопасно обрезают диапазон до границ строки.

```yukino
// Пример: прямая индексация выполняется без проверки границ.
// Для проверяемого доступа к байтам строки используйте std.strings.byte_at:
load std.strings: byte_at

set text = "Yukino"
sus {
    set byte_val = byte_at(ref text, 100)
} catch e: StringIndexError {
    println("Индекс вне диапазона: " + e.message)
}
```

## 7. Сводная таблица интринсиков: возвращаемые типы, null и паники

Ниже представлена полная справочная матрица встроенных функций и операций компилятора:

| Интринсик / Операция | Сигнатура | Может вернуть `null`? (Условия) | Поведение при ошибке |
| :--- | :--- | :--- | :--- |
| `typeof!(expr)` | `typeof!(T) -> string` | **Нет** (всегда имя типа) | **Не паникует** (вычисляется при компиляции) |
| `cast(val, "ptr<T>")` | `T -> ptr<T>` | **Да:** если `val` равен `0`, `null`, `""` или не является валидным hex-адресом | **Не паникует** (ошибочный адрес возвращает `null`) |
| `cast(str, "char")` | `string -> char` | **Нет** | Нетипизированная паника `"Panic"` (пустая строка, `null`, поврежденный UTF-8) |
| `cast(str, "int*")` | `string -> int*` | **Нет** | Нетипизированная паника `"Panic"` (нечисловые символы, пустая строка, переполнение) |
| `cast(str, "uint*")` | `string -> uint*` | **Нет** | Нетипизированная паника `"Panic"` (отрицательное число, нечисловые символы) |
| `cast(str, "float*")` | `string -> float*` | **Нет** | Нетипизированная паника `"Panic"` (некорректный формат числа с плавающей точкой) |
| `cast(str, "bool")` | `string -> bool` | **Нет** (пустая строка или `null` возвращает `false`) | Нетипизированная паника `"Panic"` с сообщением `invalid boolean syntax in string cast to bool` |
| `cast(str, "char[]")` | `string -> char[]` | **Нет** (пустая строка возвращает пустой срез) | Нетипизированная паника `"Panic"` с сообщением `invalid utf-8 in string cast to char[]` |
| `cast(chars, "string")` | `char[] -> string` | **Нет** (пустой срез возвращает пустую строку) | Нетипизированная паника `"Panic"` с сообщением `invalid unicode codepoint in char[] cast to string` |
| `cast(val, "string")` | `T -> string` | **Нет** (пустая строка при нулевой длине) | **Не паникует** (для чисел, `bool`, `char`, указателей) |
| `args()` | `() -> string[]` | **Нет** (пустой срез при отсутствии аргументов или региона) | **Не паникует** |
| `raw_args()` | `() -> string` | **Нет** (пустая строка `""` при отсутствии) | **Не паникует** |
| `exit(code)` | `int32 -> never` | **Нет** (не возвращает управление) | **Не паникует** (завершает процесс) |
| `panic(payload)` | `S -> never` | **Нет** (не возвращает управление) | Структура `payload` (заданный разработчиком тип, например `MathError`) |
| `assert(cond, [msg])` | `bool, [string] -> void` | **Нет** | Нетипизированная паника `"Panic"` с пустым сообщением (при `cond == false`) |
| `assert_eq(a, b, [msg])` | `T, T, [string] -> void` | **Нет** | Нетипизированная паника `"Panic"` с пустым сообщением (при `a != b`; сравниваются только целые числа) |
| `assert_ne(a, b, [msg])` | `T, T, [string] -> void` | **Нет** | Нетипизированная паника `"Panic"` с пустым сообщением (при `a == b`; сравниваются только целые числа) |
| `ptr_of(var)` | `T -> ptr<T>` | **Нет** (адрес переменной ненулевой) | **Не паникует** |
| `string::from_raw_parts` | `ptr<uint8>, int -> string` | **Да (внутри дескриптора):** если передан `null` указатель с длиной 0 | **Не паникует** (валидация не выполняется; поврежденный дескриптор приводит к неопределенному поведению) |
| `slice::from_raw_parts` | `ptr<T>, int, int -> T[]` | **Да (внутри дескриптора):** если передан `null` указатель с длиной 0 | **Не паникует** (валидация не выполняется) |
| `.as_ptr()` | `collection -> ptr<T>` | **Да:** если коллекция пустая или не имеет буфера | **Не паникует** |
| `.len()`, `.cap()` | `collection -> int64` | **Нет** (возвращает `0`) | **Не паникует** |
| `.is_empty()` | `collection -> bool` | **Нет** (всегда `true` или `false`) | **Не паникует** |
| `.push(elem)` | `T[] -> void` | **Нет** | **Не паникует** (при исчерпании региона элемент молча не добавляется) |
| `.pop()` | `T[] -> T?` | **Да:** возвращает `null`, если срез пуст | **Не паникует** |
| `.del(index)` | `T[] -> void` | **Нет** | Нетипизированная паника `"Panic"` с сообщением `slice index out of bounds in slice.del` (при `index >= len`) |
| `.clear()` | `T[] -> void` | **Нет** | **Не паникует** |
| `.reserve(add)` | `T[] -> void` | **Нет** | **Не паникует** (при исчерпании региона резервирование молча пропускается) |
| `.cp()` | `T[] -> T[]` | **Нет** | **Не паникует** (требует активного региона, иначе ошибка компиляции) |
| `collection[i]` | Индексация | **Нет** | **Без проверки границ** (выход за `0..len-1` не паникует, неопределенное поведение) |
| `collection[s..e]` | Срез поддиапазона | **Нет** | **Без проверки границ** (нарушение диапазона не паникует, неопределенное поведение) |
