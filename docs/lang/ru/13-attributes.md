# Атрибуты компилятора (Attributes)

Атрибуты компилятора в Yukino — это декларативные метаданные, добавляемые к элементам программы или всему модулю. Они управляют условной компиляцией, поведением оптимизатора LLVM, тестовым фреймворком и фильтрацией статических предупреждений (линтов).

> [!NOTE]
> Данный документ посвящен исключительно внутренним атрибутам языка Yukino (`#[...]` и `!#[...]`). Низкоуровневые C-атрибуты системного FFI (`|cdecl, packed, align=N|`) описаны в главе [Системный C ABI и C FFI](11-cabi.md).

## 1. Синтаксис атрибутов

### 1.1 Поэлементные атрибуты: #[attr]

Поэлементные атрибуты размещаются непосредственно перед объявлением функции, метода, структуры, класса, перечисления, поля или константы:

```yukino
#[inline]
fun fast_add(a: int32, b: int32) -> int32 {
    return a + b
}
```

Атрибуты могут принимать аргументы через круглые скобки или знак равенства:
- `#[target = "x86_64-unknown-linux-gnu"]`
- `#[target("x86_64-unknown-linux-gnu")]`
- `#[cfg(all(target_os = "linux", feature = "ssl"))]`

### 1.2 Составные пути и пространства имен: #[namespace::attr]

Атрибуты поддерживают составные пути идентификаторов через разделитель `::`. Это исключает коллизии имен между стандартными атрибутами компилятора, внешними библиотеками метапрограммирования и встроенными инструментами:

```yukino
struct UserAccount {
    #[json::rename = "user_name"]
    name: string

    #[db::primary_key]
    #[db::column = "account_id"]
    id: int64
}
```

### 1.3 Модульные внутренние атрибуты: #![attr] и !#[attr]

Модульные атрибуты применяются ко всему файлу/модулю целиком и объявляются в самом начале файла. Компилятор поддерживает канонический синтаксис `#![...]`, а также исторический синтаксис Yukino `!#[...]`:

```yukino
#![cfg(target_os = "linux")]
#![warns_ignore("unused_variable")]

public fun linux_helper() {
    space
}
```

Если условие модульного атрибута не выполняется, компилятор полностью отсекает весь модуль на этапе фильтрации AST еще до этапа разрешения имен (Name Resolution).

Помимо условной компиляции (`target`, `arch`, `feature`) и фильтра предупреждений (`ignore_warn`, `warns_ignore`) модульные атрибуты могут задавать свойства сразу всем функциям файла. Поддерживаются `deprecated`, `stable`, `inline`, `no_inline`, `inline_never`, `inline_always`, `cold` и `noreturn`:

```yukino
!#[cold]

fun helper_a() { space }
fun helper_b() { space }
```

Такой атрибут распространяется на каждую функцию, метод, статический метод и акцессор файла так, будто он объявлен непосредственно у этого объявления. Атрибут, указанный у самого объявления, имеет приоритет над файловым; в частности, любая подсказка встраивания на объявлении (`inline`, `no_inline`, `inline_never`, `inline_always`) полностью перекрывает файловую подсказку встраивания. Атрибуты `mangle` и атрибуты тестирования на уровне файла не допускаются.

### 1.4 Группировка атрибутов

Внутри одной пары скобок `#[...]` можно перечислять несколько атрибутов через запятую:

```yukino
struct CriticalError {
    message: string
    code: int32
}

#[cold, noreturn]
fun abort_critical() {
    panic(CriticalError {
        message: "critical condition violated",
        code: 501,
    })
}
```

### 1.5 Классификация атрибутов языка

В компиляторе Yukino атрибуты разделены на четкие семантические категории:
1. **Встроенные атрибуты генератора кода (`Built-in`):** `#[inline]`, `#[cold]`, `#[noreturn]`, `#[stable]`, `#[mangle]`. Управляют оптимизациями LLVM IR и C ABI.
2. **Атрибуты условной конфигурации (`Config`):** `#[cfg(...)]`, `#![cfg(...)]`, `#[cfg_attr(...)]`. Отсекают неактивные ветви AST до резолва символов.
3. **Мутации типов (`Mutation`):** `#[mutation(...)]`. Генерируют дополнительный код для типов (сериализация, конструкторы).
4. **Атрибуты инструментов (`Tool / Lint`):** `#[lint::ignore(...)]`, `#[lint::deny(...)]`, `#[lint::allow(...)]`, `#[warns_ignore(...)]`, `#[deprecated]`.
5. **Вспомогательные инертные атрибуты (`Inert Helper`):** атрибуты с путями (например, `#[json::rename]`), служащие метаданными для генераторов кода и игнорируемые бэкендом.

## 2. Условная компиляция

Атрибуты условной компиляции проверяются на этапе AST-фильтрации (`yukic-resolve::conditional`). Элементы, чьи условия не совпали с текущей целевой платформой или активными фичами, полностью удаляются из дерева программы.

### 2.1 Унифицированный атрибут конфигурации: #[cfg(...)]

Основным и наиболее выразительным инструментом условной компиляции является атрибут `#[cfg(...)]` (а на уровне модулей — `#![cfg(...)]`).

Он поддерживает произвольную вложенность булевой логики с операторами:
- `all(cond1, cond2, ...)` — логическое И (все условия должны быть истинны).
- `any(cond1, cond2, ...)` — логическое ИЛИ (хотя бы одно условие должно быть истинно).
- `not(cond)` — логическое НЕ (инверсия условия).

Внутри предикатов доступны параметры:
- `feature = "name"` — проверка активности фичи проекта (из манифеста или флага сборки).
- `target_os = "linux"` — проверка операционной системы (`"linux"`, `"windows"`, `"macos"`, `"android"`).
- `target_arch = "x86_64"` — проверка архитектуры процессора (`"x86_64"`, `"aarch64"`, `"arm"`).
- `target_env = "gnu"` — проверка ABI среды исполнения и libc (`"gnu"`, `"musl"`, `"msvc"`).

Примеры использования:

```yukino
// Активируется только на Linux x86_64 с включенной фичей ssl
#[cfg(all(target_os = "linux", target_arch = "x86_64", feature = "ssl"))]
fun init_fast_ssl() {
    space
}

// Активируется, если включена либо pico_tls, либо openssl на POSIX
#[cfg(any(feature = "pico_tls", all(target_os = "linux", feature = "openssl")))]
fun init_tls() {
    space
}

// Активируется везде, кроме Windows
#[cfg(not(target_os = "windows"))]
fun posix_socket() {
    space
}
```

### 2.2 Условное применение атрибутов: #[cfg_attr(...)]

Атрибут `#[cfg_attr(condition, attribute)]` позволяет навешивать любые другие атрибуты (инлайнинг, мутации, оптимизации) только при выполнении заданного условия:

```yukino
// Принудительно инлайнить только в релизной сборке (при отключенном debug_assertions)
#[cfg_attr(target_os = "linux", inline_always)]
fun low_level_call() {
    space
}

// Навесить мутацию сериализации только при включенной фиче "json"
#[cfg_attr(feature = "json", mutation(JsonSerialize))]
struct ConfigPayload {
    host: string
    port: int32
}
```

Если предикат истинен, компилятор динамически добавляет целевой атрибут к элементу перед последующими стадиями компиляции.

### 2.3 Исторические атрибуты target, arch, feature и синтаксис #[!attr]

Для обратной совместимости сохраняются исторические одиночные атрибуты:

- `#[target = "x86_64-unknown-linux-gnu"]` или список `#[target = ["...", "..."]]`
- `#[arch = "x86_64"]` (поддерживаются `"x86_64"`, `"arm64"`, `"arm"`)
- `#[feature = "ssl"]`
- Префиксное отрицание `#[!target = "..."]`, `#[!arch = "..."]`, `#[!feature = "..."]`

```yukino
#[target = "x86_64-pc-windows-gnu"]
fun windows_only() {
    space
}

#[!target = "x86_64-pc-windows-gnu"]
fun non_windows_only() {
    space
}
```

### 2.2 Архитектура процессора: arch

Позволяет отфильтровать код по семейству процессорной архитектуры. Поддерживаются значения `"x86_64"` и `"arm64"` (AArch64); любое другое значение приводит к ошибке компиляции. Атрибут принимает ровно одно значение (список не допускается):

```yukino
#[arch = "x86_64"]
fun process_simd() {
    // SSE/AVX инструкции
}

#[arch = "arm64"]
fun process_simd() {
    // ARM NEON инструкции
}

#[!arch = "arm64"]
fun non_arm_routine() {
    space
}
```

### 2.3 Флаги сборки и фичи: feature

Сопоставляет имя активированной фичи из секции `[features]` манифеста `yuki.toml` (или переданной через `--features`). Если атрибуту передан список строк, элемент считается активным только тогда, когда активированы все фичи из списка одновременно (в отличие от `target`, где достаточно совпадения одной из):

```yukino
struct FeatureError {
    message: string
    code: int32
}

#[feature = "ssl"]
fun connect_secure() {
    space
}

#[!feature = "ssl"]
fun connect_secure() {
    panic(FeatureError {
        message: "SSL feature is not enabled in this build",
        code: 502,
    })
}
```

## 3. Оптимизация и генерация кода функций

### 3.1 Чистые функции: #[stable]

Указывает оптимизатору LLVM, что функция является детерминированной, завершающейся и свободной от побочных эффектов.

Компилятор автоматически навешивает на функцию атрибуты LLVM:
- `nounwind`: функция гарантированно не выбрасывает исключений и не инициирует панику.
- `willreturn`: функция гарантированно завершает выполнение (не содержит бесконечных циклов).
- `memory(none)` / `readnone`: функция не читает и не модифицирует глобальное состояние памяти программы, результат зависит исключительно от переданных аргументов.

```yukino
#[stable]
fun square(x: int64) -> int64 {
    return x * x
}
```

Благодаря `#[stable]`, LLVM может безопасно объединять дублирующиеся вызовы, выполнять агрессивный Common Subexpression Elimination (CSE) и вычислять результаты на этапе компиляции.

### 3.2 Управление встраиванием: #[inline], #[inline_always], #[no_inline]

Управляет инлайнингом функций в местах их вызова:

| Атрибут | LLVM эквивалент | Описание |
| :--- | :--- | :--- |
| `#[inline]` | `inlinehint` | Дает оптимизатору сильную рекомендацию встроить тело функции |
| `#[inline("always")]` / `#[inline_always]` | `alwaysinline` | Принудительно встраивать тело функции при любых уровнях оптимизации |
| `#[inline("never")]` / `#[inline_never]` / `#[no_inline]` | `noinline` | Категорически запретить встраивание функции |

Пример использования:

```yukino
#[inline_always]
fun bit_get(mask: uint32, index: uint32) -> bool {
    return (mask & (1 << index)) != 0
}

#[no_inline]
fun heavy_diagnostic_report() {
    // Сложный код форматирования, который не должен раздувать кэш инструкций
}
```

### 3.3 Подсказки профилирования и потока: #[cold], #[noreturn]

| Атрибут | LLVM эквивалент | Назначение |
| :--- | :--- | :--- |
| `#[cold]` | `cold` | Помечает ветку/функцию как маловероятную к исполнению. Оптимизатор выносит такой код из горячего цикла |
| `#[noreturn]` | `noreturn` | Сообщает, что функция никогда не возвращает управление вызывающей стороне |

```yukino
#[cold, noreturn]
fun panic_handler(msg: string) {
    print("FATAL: ")
    print(msg)
    print("\n")
    exit(1)
}
```

### 3.4 Управление манглингом имен: #[mangle], #[!mangle]

По умолчанию все функции `fun` автоматически манглятся компилятором в безопасные символы формата `__yukifun_{fn_name}_{arg_types}__{ret_type}` (или `__yukifun_{fn_name}___{ret_type}` при отсутствии аргументов), что исключает коллизии имен с библиотекой C (libc), системными API и сторонними библиотеками. Главная точка входа `fun main` никогда не манглится.

| Атрибут | Применение | Назначение |
| :--- | :--- | :--- |
| `#[!mangle]` | `fun` | Отключает автоматический манглинг функции, сохраняя исходное («сырое») имя символа в бинарном артефакте |
| `#[mangle]` | `cfun` | Принудительно включает манглинг для C ABI функции |

Пример использования:

```yukino
// По умолчанию символ экспортируется как __yukifun_add_int32_int32__int32
fun add(a: int32, b: int32) -> int32 {
    return a + b
}

// Экспортируется с точным сырым именем @custom_entry
#[!mangle]
public fun custom_entry() -> int32 {
    return 42
}

// По умолчанию cfun экспортируется без манглинга (@native_call)
cfun native_call() -> int32 {
    return 100
}

// Принудительный манглинг для cfun (__yukifun_mangled_c_int32__int32)
#[mangle]
cfun mangled_c(val: int32) -> int32 {
    return val * 2
}
```

### 3.5 C ABI соглашение о вызове (thunk-функции): #[thunk]

Атрибут `#[thunk]` инструктирует компилятор генерировать функцию `fun` со стандартным соглашением о вызове C ABI (`LLVMCCallConv` / `cdecl`) и плоской сигнатурой без служебных параметров передачи региона возврата (`dest_region`).

Это позволяет использовать обычные функции Yukino напрямую в качестве C-совместимых указателей на функции:
- в системных потоках `std.threads: spawn(...)`;
- в качестве C-колбэков для внешних библиотек FFI;
- при передаче функций в динамические библиотеки через `std.sharedc`.

В отличие от `cfun`, функция с атрибутом `#[thunk]`:
- является полноценной функцией Yukino: внутри нее доступна вся выразительность языка;
- при необходимости автоматически инициализирует собственный локальный регион памяти (`_local_region`) для строк и объектов, корректно очищая его при завершении выполнения в отдельном потоке ОС;
- не требует обязательного объявления фиктивного параметра `arg: ptr<void>`, если входные данные не передаются.

```yukino
load std.threads: spawn, join
load std.io: println

#[thunk]
fun worker_routine() {
    println("Фоновый поток запущен без параметров!")
}

#[thunk]
fun worker_with_arg(arg: ptr<void>) {
    println("Фоновый поток получил указатель: ${arg}")
}

fun main() {
    // Передача функции без аргументов
    set h1 = spawn(cast(worker_routine, "ptr<void>"))
    join(h1)

    // Передача функции с аргументом
    set h2 = spawn(cast(worker_with_arg, "ptr<void>"), null)
    join(h2)
}
```

## 4. Атрибуты встроенного тестирования

> [!NOTE]
> Подробное руководство по организации тестов, атрибутам, конфигурации и тестовому раннеру `yukino test` вынесено в отдельный документ: [16. Тестирование и тест-раннер](16-tests.md).

### 4.1 Маркировка тестов: #[test]

Помечает функцию верхнего уровня без аргументов, без возвращаемого значения и без генерик-параметров как модульный тест:

```yukino
#[test]
fun test_addition() {
    assert_eq(2 + 2, 4)
}
```

Атрибуты `#[should_panic]`, `#[ignore]` и `#[timeout_ms]` допустимы только вместе с `#[test]` — их применение к обычной функции приводит к ошибке компиляции E0429.

### 4.2 Ожидание паники: #[should_panic]

Тест считается пройденным только в том случае, если при его исполнении была выброшена паника (`panic`). Поддерживается также проверка подстроки ожидаемого сообщения паники:

```yukino
// Тест успешен, если вызов divisor == 0 выбросил панику
#[test, should_panic]
fun test_zero_division() {
    set zero = 0
    set res = 10 / zero
}

struct DescriptorError {
    message: string
    code: int32
}

// Ожидаемое сообщение паники (сопоставление подстроки в ранере)
#[test, should_panic = "invalid handle"]
fun test_bad_descriptor() {
    panic(DescriptorError {
        message: "invalid handle: -1",
        code: 503,
    })
}
```

### 4.3 Пропуск тестов: #[ignore]

Помечает тест как временно отключенный. При наличии пропущенных тестов компилятор выдает предупреждение W0423:

```yukino
#[test, ignore]
fun test_long_benchmarks() {
    // Долгий сетевой или стресс-тест
}

#[test, ignore = "Requires running PostgreSQL container"]
fun test_db_integration() {
    // Интеграционный тест базы данных
}
```

Для запуска пропущенных тестов раннер `yukino test` поддерживает флаги `--ignored` (запуск только пропущенных) и `--include-ignored` (запуск всех тестов).

### 4.4 Индивидуальный таймаут: #[timeout_ms]

Задает предельное время исполнения отдельного теста в миллисекундах. Если тест превышает указанное время, изолированный процесс-воркер принудительно останавливается таймером раннера:

```yukino
#[test, timeout_ms = 500]
fun test_fast_io() {
    // Тест упадет по таймауту, если исполнение займет более 500 мс
}
```

## 5. Диагностика и линтер

### 5.1 Управление линтером: #[lint::ignore], #[lint::deny], #[lint::allow]

Компилятор Yukino предоставляет гибкую систему управления статическим анализом и предупреждениями (`yukic-driver::lint`) через пространство имен `lint::`:

- **`#[lint::ignore(...)]` / `#[lint::allow(...)]`** — подавляет указанные предупреждения линтера.
- **`#[lint::deny(...)]`** — эскалирует предупреждения в фатальные ошибки компиляции (`DiagnosticSeverity::Error`), приводящие к немедленной остановке сборки с ненулевым кодом выхода.
- Обратная совместимость: поддерживаются устаревшие формы `#[ignore_warn(...)]`, `#[warns_ignore(...)]`, `#[deny_warn(...)]` и `#[warns_deny(...)]`.

#### Области действия

1. **Уровень модуля (`#![...]`):** действует на весь файл и все объявленные в нем функции, типы и импорты:
   ```yukino
   #![lint::deny("unused_variable")]
   #![lint::ignore("unused_import")]
   ```
2. **Уровень элементов и функций (`#[...]`):** атрибут размещается непосредственно над конкретным элементом (`fun`, `cfun`, `class`, `struct`, метод):
   ```yukino
   #[lint::ignore("unused_variable")]
   fun debug_handler(unused_ctx: int32) -> int32 {
       return 0
   }

   #[lint::deny("unused_symbol")]
   fun critical_task() -> int32 {
       // Любая неиспользуемая переменная или символ здесь вызовет ошибку компиляции
       return 42
   }
   ```

#### Формат аргументов

Атрибуты принимают список имен правил в виде строк либо идентификаторов:
- Имена конкретных предупреждений: `"unused_variable"` (или `unused_variable`), `"unused_import"`, `"dead_function"`.
- Коды предупреждений: `"W0001"`, `"W0002"`, `"W0003"`.
- Имена групп предупреждений:
  - `"unused_symbol"` — включает `unused_variable`, `unused_import`, `dead_function`.
  - `"predictable_code"` — включает `predictable_condition`, `unreachable_code`.
  - `"performance_hints"` — включает `suggest_switch`, `suggest_stable`.
  - `"code_clarity"` — включает `pointless_mutability`, `redundant_parentheses`, `empty_block`, `test_ignored`.

```yukino
// Пространство имен lint::
#![lint::deny(unused_symbol)]
#![lint::ignore("predictable_code", "performance_hints")]

// Устаревший синтаксис на уровне модуля и функции
!#[ignore_warn("unused_variable")]
!#[warns_ignore("empty_block")]
#[warns_ignore("dead_function")]
fun legacy_helper() {
    space
}
```

### 5.2 Устаревший код: #[deprecated]

Используется для маркировки устаревших API перед их окончательным удалением. При вызове или использовании помеченной сущности компилятор генерирует предупреждение статического анализа **`W0418`** (`deprecated_usage`, алиасы `deprecated_item` или `deprecated`). Атрибут принимает необязательную строку с пояснением:

```yukino
#[deprecated = "Use String.trim() instead"]
fun strip_whitespace(s: string) -> string {
    return s.trim()
}

fun main() {
    // Вызовет warning[W0418]: function 'strip_whitespace' is deprecated: Use String.trim() instead
    set res = strip_whitespace("  hello  ")
}
```

#### Синтаксис и аргументы

Атрибут поддерживает как простую форму без аргументов, так и форму с указанием причины или альтернативы:
- `#[deprecated]` — выводит базовое предупреждение: `use of deprecated function 'name'`.
- `#[deprecated = "причина"]` или `#[deprecated("причина")]` — добавляет поясняющий текст к предупреждению: `use of deprecated function 'name': причина`.

#### Поддерживаемые целевые сущности

- **Функции (`fun`, `cfun`):** предупреждение генерируется в месте вызова функции.
- **Методы классов и структур:** предупреждение генерируется при вызове метода экземпляра или статического метода.
- **Структуры (`struct`) и классы (`class`):** предупреждение генерируется при создании экземпляра (`StructInit`, `ClassInit`) и в аннотациях типов.
- **Перечисления (`enum`) и псевдонимы типов (`type`):** предупреждение генерируется при обращении к типу или сопоставлении с образцом.

#### Изоляция устаревшего кода

Если функция или метод **сама** помечена атрибутом `#[deprecated]`, вызовы других устаревших сущностей внутри ее тела **не вызывают** предупреждений. Это позволяет безопасно реализовывать устаревшие переходные обёртки без лишнего диагностического шума.

#### Управление предупреждением через линтер

Предупреждение `W0420` относится к группе `code_clarity` и поддерживает управление через `#[lint::ignore]` и `#[lint::deny]`:

```yukino
// Подавление предупреждений об устаревших сущностях на уровне модуля
#![lint::ignore(deprecated_item)]

// Либо эскалация использования устаревших сущностей в фатальную ошибку сборки
#![lint::deny(deprecated)]
```

Компилятор выводит предупреждение `W0418` (имя `deprecated_usage`) в каждом месте вызова устаревшей функции или метода. Функции помечаются атрибутом непосредственно, а методы классов и структур — атрибутом на объявлении метода. Имя предупреждения в сообщении включает необязательный пояснительный текст: `function 'strip_whitespace' is deprecated: Use String.trim() instead`.

Предупреждение можно подавить глобально через `ignore_warn`:

```yukino
!#[ignore_warn("deprecated_usage")]
```

Имя, встречающееся и у устаревшей, и у обычной функции (или метода разных типов), считается неоднозначным и предупреждения не вызывает. Файловый атрибут `!#[deprecated]` помечает устаревшими все функции и методы модуля.
