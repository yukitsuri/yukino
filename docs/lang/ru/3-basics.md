## 1. Переменные: set и явная мутация rewrite

### 1.1 Объявление переменных

Все локальные переменные объявляются ключевым словом `set`. Тип выводится автоматически либо указывается явно через двоеточие:

```yukino
// Автоматический вывод типа
set count = 0                // int64
set ratio = 3.14             // float64
set active = true            // bool
set title = "Yukino"         // string

// Явное указание типа
set buffer_size: int64 = 4096
set scale: float32 = 1.5
```

Целочисленный литерал без суффикса по умолчанию выводится как `int64`, дробный — как `float64`. Литерал с `u`-суффиксом (`u8`..`u64`) становится беззнаковым и выводится как `uint64`; суффиксы `i8`..`i64` и `f32`/`f64` распознаются компилятором, но на выведенный по умолчанию тип не влияют. При явной аннотации типа литерал приводится к нему, если значение помещается в диапазон типа.

### 1.2 Правило мутации rewrite

> [!IMPORTANT]
> В Yukino **запрещено** изменять переменные, поля или элементы коллекций обычным синтаксисом `x = 10`. Это приведет к синтаксической ошибке компилятора E0201 (expected expression).

Любая модификация состояния обязана начинаться с ключевого слова `rewrite`:

```yukino
set balance = 100

// ОШИБКА КОМПИЛЯЦИИ:
// balance = 200

// ПРАВИЛЬНО:
rewrite balance = 200
rewrite balance += 50
rewrite balance -= 10

// Мутация элементов массивов и полей структур:
set numbers = [1, 2, 3]
rewrite numbers[0] = 10

// User — структура с полями name и score
set user = User { name: "Alice", score: 42 }
rewrite user.score += 1
```

Ключевое слово `rewrite` делает места возникновения побочных эффектов очевидными при аудите кода.

### 1.3 Деструктуризация кортежей

Yukino поддерживает распаковку кортежей непосредственно при объявлении через `set`:

```yukino
set coords = (10, 20)
set (x, y) = coords
```

### 1.4 Несколько инструкций в одной строке

С помощью ";" можно поместить несколько инструкций в одну строку:

```
set a = 1; set b = 2
```

## 2. Неизменяемые константы: static

Для глобальных неизменяемых значений уровня модуля или блока используется `static`. Инициализатор уровня модуля со значением-литералом вычисляется на этапе компиляции и попадает в секцию констант; локальный `static` внутри функции инициализируется при выполнении, но так же неизменяем:

```yukino
// Константы уровня модуля
static MAX_CONNECTIONS: int32 = 1000
static APP_PREFIX: string = "app_v1"

fun get_limit() -> int32 {
    // Локальная константа в теле функции
    static LOCAL_TIMEOUT: int64 = 5000
    return MAX_CONNECTIONS
}
```

Попытка применить `rewrite` к идентификатору `static` пресекается компилятором на этапе типизации (ошибка E0503: cannot reassign static constant).

## 3. Операторы, арифметика и приоритеты

Yukino обладает строгой статической типизацией выражений: **неявные преобразования типов (implicit coercion) между числовыми типами запрещены**. Нельзя сложить `int32` и `int64` или `float32` и `float64` без явного вызова `cast<T>(...)`.

### 3.1 Арифметические операторы

| Оператор | Название | Пример | Описание |
| :--- | :--- | :--- | :--- |
| `+` | Сложение / конкатенация | `a + b` | Сложение чисел одного типа или конкатенация строк (`string + string`) |
| `-` | Вычитание | `a - b` | Вычитание чисел |
| `*` | Умножение | `a * b` | Умножение чисел |
| `/` | Деление | `a / b` | Целочисленное деление с усечением к нулю (`sdiv`/`udiv`) или FP-деление |
| `%` | Остаток от деления | `a % b` | Вычисление остатка (`srem`/`urem`) |
| `**` | Возведение в степень | `a ** b` | Правоассоциативное возведение в степень целых чисел и чисел с плавающей точкой |
| `-` (унарный) | Отрицание знака | `-x` | Изменение знака числа |

Пример использования:

```yukino
set sum = 10 + 20            // 30
set diff = 50 - 15           // 35
set prod = 6 * 7             // 42
set quot = 20 / 3            // 6 (целочисленное деление)
set rem = 20 % 3             // 2
set pwr = 2 ** 4             // 16
set neg = -pwr               // -16
```

### 3.2 Побитовые операторы

Побитовые операторы применимы только к целочисленным типам (`int8..int64`, `uint8..uint64`). Оба операнда должны быть одного типа.

| Оператор | Название | Пример | Описание |
| :--- | :--- | :--- | :--- |
| `&` | Побитовое И (AND) | `a & b` | Побитовое логическое умножение |
| `\|` | Побитовое ИЛИ (OR) | `a \| b` | Побитовое логическое сложение |
| `^` | Побитовое исключающее ИЛИ (XOR) | `a ^ b` | Побитовое сложение по модулю 2 |
| `~` (унарный) | Побитовое НЕ (NOT) | `~x` | Инверсия всех битов числа |
| `<<` | Сдвиг влево | `a << b` | Сдвиг битов влево с заполнением нулями |
| `>>` | Сдвиг вправо | `a >> b` | Арифметический (для знаковых) или логический (для беззнаковых) сдвиг вправо |

Пример:

```yukino
set mask = 0xFF & 0x0F       // 0x0F (15)
set flags = 1 | 2            // 3
set toggled = flags ^ 1      // 2
set inverted = ~0            // Все биты установлены в 1 (-1)
set shifted_left = 1 << 4    // 16
set shifted_right = 32 >> 2  // 8
```

### 3.3 Операторы сравнения и проверки типов

Все операторы сравнения возвращают значение типа `bool`:

| Оператор | Название | Описание |
| :--- | :--- | :--- |
| `==` | Равенство | Сравнение примитивных значений, указателей или nullable с `null` |
| `!=` | Неравенство | Проверка неравенства примитивов или nullable с `null` |
| `<` | Меньше | Числовое сравнение |
| `<=` | Меньше либо равно | Числовое сравнение |
| `>` | Больше | Числовое сравнение |
| `>=` | Больше либо равно | Числовое сравнение |
| `is` | Проверка типа | Проверка принадлежности значения размеченному объединению (tagged union) |

Пример:

```yukino
set is_equal = (10 == 10)    // true
set is_less = (5 < 10)       // true

set value: int32 | string = 42
if value is int32 {
    // Ветка, если значение является int32
    space
}
```

### 3.4 Логические операторы

Операторы `&&`, `||` и `!` работают со значениями типа `bool` и могут использоваться в любом выражении, включая условия управляющих конструкций (`if`, `elif`, `while`):

| Оператор | Название | Пример | Описание |
| :--- | :--- | :--- | :--- |
| `&&` | Логическое И | `cond1 && cond2` | Истинно, если оба операнда истинны |
| `\|\|` | Логическое ИЛИ | `cond1 \|\| cond2` | Истинно, если хотя бы один операнд истинен |
| `!` (унарный) | Логическое НЕ | `!cond` | Инвертирует булево значение |

```yukino
set ready = true
set error_count = 0

// Идиоматичный синтаксис без лишних скобок:
if ready && error_count == 0 {
    space
} elif !ready || error_count > 5 {
    space
}

// Скобки допустимы при явной необходимости изменить порядок вычислений:
if (ready || error_count == 0) && timeout == 0 {
    space
}
```

> [!NOTE]
> В Yukino операторы сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`) обладают более высоким приоритетом (Binding Power `12`–`15`), чем логические операторы `&&` (`10`) и `||` (`8`). Поэтому выражения вида `ready && error_count == 0` парсятся компилятором однозначно и не требуют обрамления сравнений в круглые скобки `(error_count == 0)`. Круглые скобки используются только для изменения естественного приоритета операторов.

### 3.5 Составные операторы мутации (rewrite)

Составные операторы комбинируют вычисление и запись и **всегда** предваряются ключевым словом `rewrite`:

```yukino
set x = 10

rewrite x += 5               // x = x + 5 (15)
rewrite x -= 3               // x = x - 3 (12)
rewrite x *= 2               // x = x * 2 (24)
rewrite x /= 4               // x = x / 4 (6)
rewrite x %= 4               // x = x % 4 (2)
rewrite x **= 3              // x = x ** 3 (8)

rewrite x &= 7               // Побитовое И с присваиванием
rewrite x |= 8               // Побитовое ИЛИ с присваиванием
rewrite x ^= 3               // Побитовое XOR с присваиванием
rewrite x <<= 2              // Битовый сдвиг влево с присваиванием
rewrite x >>= 1              // Битовый сдвиг вправо с присваиванием
```

### 3.6 Операторы работы с памятью и Null

- `??` (Null Coalescing): безопасное извлечение значения из `T?` с запасным вариантом:
  ```yukino
  set name: string? = null
  set safe_name = name ?? "anonymous" // Если name == null, вернет "anonymous"
  ```
- `?.` (Safe Call): безопасная навигация по полям nullable-структур и классов:
  ```yukino
  set email: string? = user?.profile?.email
  ```
- `ref expr` / `ref ~expr`: взятие неизменяемой или изменяемой ссылки при передаче аргументов функции:
  ```yukino
  inspect(ref my_struct)
  mutate(ref ~my_struct)
  ```

> [!NOTE]
> Подробно работа с nullable-значениями, защита от null и операторы `??` и `?.` рассматриваются в документе [4-types.md](4-types.md). Полная модель управления памятью, передача по ссылке `ref`/`ref ~`, заимствование и аффинное владение подробно описаны в документе [6-memory.md](6-memory.md).

### 3.7 Таблица приоритетов (Binding Power)

Yukino использует алгоритм синтаксического анализа выражений Пратта (Pratt parsing). Приоритет каждого оператора определяется числовой силой связывания (Binding Power). Для бинарных инфиксных операторов сила связывания задается парой `(Left BP, Right BP)`:
- Чем выше числовое значение Binding Power, тем сильнее оператор притягивает соседние операнды.
- **Левоассоциативные операторы**: удовлетворяют правилу `Left BP < Right BP`. При цепочке одинаковых операторов (`a + b + c`) левая операция связывается первой: `(a + b) + c`.
- **Правоассоциативные операторы**: удовлетворяют правилу `Left BP > Right BP`. При цепочке одинаковых операторов (`2 ** 3 ** 2`) правая операция связывается первой: `2 ** (3 ** 2)`.

Ниже представлена полная таблица всех операторов языка Yukino в порядке убывания их приоритета (ранг 1 — наивысший приоритет):

| Ранг | Операторы | Binding Power | Ассоциативность | Описание |
| :---: | :--- | :---: | :--- | :--- |
| **1** | `()` `[]` `.` `?.` | `34` (Postfix) | Слева направо (Left) | Вызов функции, индексация, доступ к полю, безопасная навигация |
| **2** | `-` `!` `~` `ref` `ref ~` `...` | `32` (Prefix) | Справа налево (Prefix) | Унарный минус, логическое НЕ, побитовое НЕ, взятие ссылки, spread |
| **3** | `**` | `(31, 30)` | **Справа налево (Right)** | Возведение в степень (`2 ** 3 ** 2 == 2 ** 9`) |
| **4** | `*` `/` `%` | `(28, 29)` | Слева направо (Left) | Умножение, деление, остаток от деления |
| **5** | `+` `-` | `(26, 27)` | Слева направо (Left) | Сложение (и конкатенация строк), вычитание |
| **6** | `<<` `>>` | `(24, 25)` | Слева направо (Left) | Побитовые сдвиги влево и вправо |
| **7** | `..` `..=` | `(22, 23)` | Слева направо (Left) | Конструирование диапазонов (range) |
| **8** | `&` | `(20, 21)` | Слева направо (Left) | Побитовое И |
| **9** | `^` | `(18, 19)` | Слева направо (Left) | Побитовое исключающее ИЛИ (XOR) |
| **10** | `\|` | `(16, 17)` | Слева направо (Left) | Побитовое ИЛИ |
| **11** | `<` `<=` `>` `>=` | `(14, 15)` | Слева направо (Left) | Реляционные сравнения |
| **12** | `==` `!=` `is` | `(12, 13)` | Слева направо (Left) | Равенство, неравенство, проверка типа (`expr is Type`) |
| **13** | `&&` | `(10, 11)` | Слева направо (Left) | Логическое И |
| **14** | `\|\|` | `(8, 9)` | Слева направо (Left) | Логическое ИЛИ |
| **15** | `??` | `(6, 7)` | Слева направо (Left) | Слияние с null (Null-coalescing) |
| **16** | `\|>` | `(4, 5)` | Слева направо (Left) | Конвейерный вызов (Pipe operator, `x \|> f` эквивалентно `f(x)`) |
| **17** | `? :` | `(3, 2)` | **Справа налево (Right)** | Тернарный условный оператор (`cond ? then_val : else_val`) |

## 4. Управляющие конструкции

### 4.1 Ветвления: if, elif, else и тернарный оператор

Условия в `if` не требуют круглых скобок. Для промежуточных проверок используется ключевое слово `elif`:

```yukino
set score = 85

if score >= 90 {
    // Ветка при score >= 90
} elif score >= 75 {
    // Ветка при 75 <= score < 90
} else {
    // Ветка по умолчанию
}

// Тернарный оператор для компактных условных выражений:
set status = score >= 50 ? "passed" : "failed"
```

### 4.2 Циклы: while, loop, for и метки

Yukino предоставляет три основные конструкции циклов: `while`, `loop` и `for`. Любой цикл может быть прерван оператором `break` или переведен на следующую итерацию оператором `continue`.

#### 1. Цикл с предусловием: while

Цикл `while` выполняется до тех пор, пока булево условие истинно:

```yukino
set i = 0
while i < 5 {
    rewrite i += 1
}
```

#### 2. Бесконечный цикл: loop

Конструкция `loop` оптимизирована компилятором под бесконечный цикл (в LLVM генерирует безусловный переход `br label %loop.body` без лишних проверок условий на входе). Прерывается операторами `break`, `return` или `panic`:

```yukino
set attempts = 0
loop {
    rewrite attempts += 1
    if attempts >= 3 {
        break
    }
}
```

#### 3. Цикл итерации: for

Цикл `for` используется для итерации по числовым диапазонам. Итерация по массивам и другим коллекциям в текущей реализации компилятора не поддерживается (ошибка компиляции: unsupported iterator in for loop):

- **Полуинтервал `start..end`**: диапазон `[start, end)`, не включающий конечное значение `end`:
  ```yukino
  // Выведет числа от 0 до 4
  for i in 0..5 {
      print("${i} ")
  }
  ```

- **Включающий диапазон `start..=end`**: диапазон `[start, end]`, включающий конечное значение `end`:
  ```yukino
  // Выведет числа от 0 до 5
  for i in 0..=5 {
      print("${i} ")
  }
  ```

Переменная цикла при итерации по диапазону имеет тип `int64`.

#### 4. Именованные метки циклов (Labels)

При глубокой вложенности циклов операторы `break` и `continue` по умолчанию относятся к самому внутреннему циклу. Чтобы прервать внешний цикл или перейти на его следующую итерацию, используются метки.

Язык поддерживает три варианта синтаксиса объявления меток:
1. **Префиксная метка** (рекомендуемый стиль): `outer: while ...`, `outer: for ...`, `outer: loop { ... }`
2. **Префиксная метка с двоеточием**: `:outer while ...`, `:outer for ...`, `:outer loop { ... }`
3. **Инлайн-метка**: `while outer: ...`, `for outer: ...`, `loop outer: { ... }`

##### Пример выхода из внешнего цикла (break label):

```yukino
outer: for row in 0..10 {
    for col in 0..10 {
        if row * col > 50 {
            // Мгновенный выход из обоих циклов (включая внешний outer)
            break outer
        }
    }
}
```

##### Пример перехода на следующую итерацию внешнего цикла (continue label):

```yukino
outer: while true {
    while true {
        // Переход к следующей итерации внешнего цикла outer
        continue outer
    }
}
```

##### Семантика меток и очистка ресурсов (defer LIFO)

> [!IMPORTANT]
> Если при выполнении `break label` или `continue label` поток управления выходит за пределы одного или нескольких вложенных блоков, содержащих отложенные вызовы `defer`, компилятор гарантирует вызов всех промежуточных `defer` в строгом порядке LIFO (от внутренних к внешним) перед переходом на целевой блок LLVM.

```yukino
outer: loop {
    defer print("cleanup outer\n")
    inner: loop {
        defer print("cleanup inner\n")
        break outer
    }
}
// Вывод программы:
// cleanup inner
// cleanup outer
```

### 4.3 Заглушка space

Если блок или тело функции намеренно оставляются пустыми (например, интерфейсная заглушка, игнорируемое событие), компилятор генерирует предупреждение. Чтобы явно подтвердить отсутствие действий, используется ключевое слово `space`:

```yukino
fun on_tick() {
```
