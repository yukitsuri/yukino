## 1. Примитивные типы данных

Компилятор строго разделяет размеры и знаковость типов. Неявные расширения или сужения не допускаются (для явного приведения используется интринсик `cast`):

| Категория | Типы | Примечание |
| :--- | :--- | :--- |
| **Знаковые целые** | `int8`, `int16`, `int32`, `int64` | По умолчанию целочисленные литералы без суффикса выводятся как `int64` |
| **Беззнаковые целые** | `uint8`, `uint16`, `uint32`, `uint64` | `uint8` также представляет собой байт. Литералы с `u`-суффиксом (`u8`..`u64`) беззнаковые и выводятся как `uint64` |
| **С плавающей точкой** | `float32`, `float64` | IEEE 754. По умолчанию дробные литералы — `float64` |
| **Логический** | `bool` | Литералы `true` и `false` |
| **Символьный** | `char` | 32-битный скалярный Unicode code point (например, `'A'`, `'ゆ'`) |
| **Строковый** | `string` | Неизменяемый 16-байтный дескриптор среза байтов `{ ptr, len }` (Copy-тип) |
| **Служебные** | `void`, `never`, `null` | `void` — пустота; `never` — невозврат (напр. `exit()`); `null` — отсутствие значения |

Числовой литерал приводится к аннотированному типу, если значение помещается в его диапазон: `set small: int8 = 100` допустимо, а `set big: int8 = 300` — ошибка несовпадения типов. Суффиксы `i8`..`i64` и `f32`/`f64` распознаются компилятором, но на выведенный по умолчанию тип не влияют.

Строки `string` представляют собой неизменяемые последовательности байтов, упакованные в 16-байтный дескриптор `{ ptr, len }`. Они являются **Copy-типами**: при присваивании или передаче аргументом копируется только дескриптор, обе переменные остаются валидными, и передавать строки по ссылке `ref` для чтения не требуется (подробнее см. в главе [Строки и текст](8-strings.md)).

## 2. Составные типы

### 2.1 Кортежи (tuples)

Группируют фиксированное количество разнородных значений:

```yukino
set pair: (string, int32) = ("port", 8080)

// Доступ по позиционному индексу .0, .1 (рекомендуется явная аннотация типа)
set key: string = pair.0
set port: int32 = pair.1

// Деструктуризация кортежа
set (name, code) = pair
```

### 2.2 Массивы

Массивы бывают динамическими `T[]` и фиксированными `T[N]`:

```yukino
// Динамический массив
set list: int32[] = [10, 20, 30]
// Создание пустого динамического массива без литерала:
set empty_list: int32[]

// Фиксированный массив с явным списком значений (количество элементов обязано точно совпадать с N)
set buffer: uint8[4] = [0, 0, 0, 0]

// Глобальные статические массивы (поддерживаются все примитивные числовые типы, строки и bool)
static GLOBAL_BUF: uint8[4] = [1, 2, 3, 4]
static GLOBAL_INTS: int32[] = [10, 20, 30]

// Выделение массива заданной длины без литерала (память автоматически зануляется):
set ints: int32[100]

// Индексация
set first = list[0]
```

### 2.3 Карты (map)

Ассоциативные массивы пар ключ-значение:

```yukino
set user_ages: map<string, int32> = {
    "Alice": 28,
    "Bob": 34
}

set alice_age = user_ages["Alice"]
```

## 3. Опциональные типы (T?) и безопасность null

### 3.1 Проблема null и философия безопасности Yukino

Создатель концепции `null` сэр Тони Хоар назвал свое изобретение «ошибкой на миллиард долларов». В большинстве классических языков (Си, Java, C#, Python, JavaScript) любая ссылка на объект или строку может неожиданно оказаться пустой (`null` или `None`). Если программист забыл вручную проверить значение перед использованием, программа аварийно падает прямо у пользователя:
- в Java — пресловутый `NullPointerException`;
- в Си и C++ — фатальный `Segmentation fault`;
- в Python — `AttributeError: 'NoneType' object has no attribute ...`.

Yukino решает эту проблему в корне: **в Yukino все типы данных по умолчанию гарантированно НЕ МОГУТ быть null**!

Если переменная или поле объявлены как `string`, `int32` или `User`, компилятор дает 100% статическую гарантию, что там всегда находится настоящее, корректное значение:

```yukino
// ОШИБКА КОМПИЛЯЦИИ: E0401 (expected `string`, found `null`)
// set name: string = null

// ОШИБКА КОМПИЛЯЦИИ: E0401 (expected `int32`, found `null`)
// set age: int32 = null
```

Если программа скомпилировалась, вы можете быть абсолютно уверены: обращение к полям и методам таких переменных никогда не приведет к падению из-за `null`.

### 3.2 Синтаксис опциональных типов T?

Но в реальных программах значение может отсутствовать:
- пользователь не указал номер телефона при регистрации;
- в базе данных не найдена запись с указанным ID;
- файл конфигурации не содержит опциональный параметр.

Чтобы явно выразить, что переменная может либо содержать значение, либо быть пустой, к имени типа добавляется знак вопроса `?`:

```yukino
set user_phone: string? = null // Переменная типа string? может хранить null
set score: int32? = 100        // Либо настоящее целое число
```

Семантически `T?` — это объединение типов `T | null`.

### 3.3 Возврат T? из функций

Самый частый и правильный сценарий использования опциональных типов — возврат результата из функций поиска или извлечения данных:

```yukino
struct User {
    id: int32
    name: string
    email: string? // email тоже может быть не заполнен
}

fun find_user_by_id(id: int32) -> User? {
    if id == 42 {
        return User {
            id: 42,
            name: "Алиса",
            email: "alice@example.com",
        }
    }
    // Если пользователя с таким id нет в базе:
    return null
}
```

Сигнатура `-> User?` честно и прямо предупреждает любого, кто вызывает эту функцию: *«Будь готов, что пользователя может не оказаться, и функция вернет null»*.

### 3.4 Почему нельзя просто присвоить T? в T

Что произойдет, если мы попытаемся результат функции `find_user_by_id` записать в обычную (не-nullable) переменную?

```yukino
set maybe_user: User? = find_user_by_id(10)

// ОШИБКА КОМПИЛЯЦИИ: E0401: expected `User`, found `User?`
// set user: User = maybe_user
```

Компилятор категорически откажется собирать такую программу! И это намеренное решение: если бы компилятор разрешил такое присваивание, а в переменной оказался `null`, любая последующая попытка обратиться к `user.name` привела бы к крашу.

Yukino заставляет разработчика **явно решить, как поступить, если значения нет**.

### 3.5 Способы извлечения значения (??, ?., проверки)

Язык предоставляет четыре удобных и безопасных способа работы со значениями `T?`:

#### Способ 1: Оператор слияния с null (?? — Null-Coalescing)
Идеально подходит, когда при отсутствии значения можно подставить разумный вариант по умолчанию. Оператор `??` распаковывает `T?`: если значение есть — берет его, а если там `null` — подставляет значение справа:

```yukino
set maybe_id: int64? = null

// Если maybe_id равен null, берется 0.
// Результат safe_id ГАРАНТИРОВАННО имеет не-nullable тип int64:
set safe_id: int64 = maybe_id ?? 0

set raw_nickname: string? = null
// display_name гарантированно имеет не-nullable тип string:
set display_name: string = raw_nickname ?? "Анонимный гость"
```

#### Способ 2: Безопасная навигация (?.)
Предотвращает падение при обращении к полям или методам у nullable-объектов. Если левая часть выражения равна `null`, компилятор не паникует, а просто возвращает `null` для всей цепочки:

```yukino
struct Profile {
    avatar_url: string
}

struct Account {
    profile: Profile?
}

set account: Account? = null

// Если account == null или profile == null, вернется null без ошибки времени выполнения:
set avatar: string? = account?.profile?.avatar_url
```

Можно объединять `?.` и `??` в элегантные безопасные выражения:

```yukino
// Если account == null или profile == null, подставится картинка по умолчанию:
set safe_avatar: string = account?.profile?.avatar_url ?? "/default_avatar.png"
```

#### Способ 3: Явная проверка на равенство `!= null`
Если значение по умолчанию не имеет смысла, а отсутствие данных — это ошибка, выполняется проверка через условие:

```yukino
struct NotFoundError {
    message: string
    code: int32
}

set user: User? = find_user_by_id(10)

if user == null {
    panic(NotFoundError {
        message: "пользователь с данным ID не найден",
        code: 404,
    })
}
```

#### Способ 4: Проверка через оператор `is`
Оператор `is` проверяет принадлежность типа:

```yukino
set val: int32? = 42

if val is null {
    println("Значение отсутствует")
} else {
    println("Значение присутствует")
}
```

### 3.6 Автоматическое расширение T в T?

В обратную сторону (от не-nullable к nullable) присваивание абсолютно безопасно и выполняется компилятором автоматически:

```yukino
set real_number: int32 = 42

// Не-nullable значение int32 свободно входит в объединение int32 | null:
set optional_number: int32? = real_number // OK: не требует операторов или кастов
```

## 4. Объединения типов (Unions) и оператор is

Синтаксис `T1 | T2` позволяет объявлять переменные, которые могут хранить один из нескольких допустимых типов:

```yukino
set payload: int32 | bool = 42

// Проверка типа оператором is
if payload is int32 {
    // payload является int32
}
```

Оператор `is` также используется для проверки равенства `null` (`val is null`) и динамической проверки классов и интерфейсов при наследовании (`obj is MyInterface`).

## 5. Псевдонимы типов (type)

Ключевое слово `type` позволяет объявлять именованные псевдонимы для типов данных:

```yukino
type UserId = int64
type ResponsePair = (int32, string)
type ResultHandler = fun(int32) -> void
```

## 6. Сопоставление с образцом: switch

Конструкция `switch` сопоставляет значение с шаблонами. В отличие от некоторых других языков, здесь **нет** ключевого слова `case`, а для ветки по умолчанию используется `else ->`:

```yukino
set code = 200

switch code {
    200 -> {
        // Успех
    }
    201 | 204 -> {
        // Создано или пустой ответ
    }
    404 -> {
        // Не найдено
    }
    else -> {
        // Все остальные случаи
    }
}
```

### 6.1 Связывание переменных и охранные выражения (guards)

Шаблон может связывать переменную и накладывать условие через `if`:

```yukino
set score = 85

switch score {
    100 -> {
        // Идеальный результат
    }
    s if s >= 80 -> {
        // Отлично, s доступна внутри блока
    }
    s if s >= 50 -> {
        // Удовлетворительно
    }
    else -> {
        // Неудача
    }
}
```

## 7. Обобщенные типы (Generics)

Yukino поддерживает синтаксис обобщенных типов (параметрический полиморфизм) для классов, интерфейсов и коллекций, позволяя создавать переиспользуемые структуры данных с проверкой типов на этапе компиляции.

Параметры типов перечисляются в угловых скобках `<...>` после имени типа:

```yukino
// Объявление обобщенного класса с параметрами K и V
public class HashMap<K, V> {
    handle: ptr<uint8>

    public fun init() {
        rewrite this.handle = yukistd_map_new()
    }

    public fun set(key: K, val: V) {
        // реализация операции сохранения
    }

    public fun get(key: K) -> V? {
        // реализация поиска значения
    }
}
```

### 7.1 Инстанцирование и использование

При создании экземпляра обобщенного типа аргументы конкретных типов указываются явно:

```yukino
// Создание экземпляра карты с типами ключа и значения string
set map = init HashMap<string, string>()
map.set("HOST", "127.0.0.1")
set host = map.get("HOST")
```

Обобщенные типы могут использоваться в качестве типов переменных, аргументов функций и возвращаемых значений:

```yukino
public fun all() -> HashMap<string, string> {
    set map = init HashMap<string, string>()
    // заполнение данными...
    return map
}
```

### 7.2 Интеграция с системой памяти и регионами

Экземпляры обобщенных классов подчиняются общим правилам региональной системы памяти Yukino. Если функция возвращает экземпляр обобщенного класса, компилятор применяет механизм передачи региона назначения (Destination-Passing Style), гарантируя аллокацию возвращаемого объекта в регионе вызывающей стороны без преждевременного уничтожения данных при выходе из функции.
