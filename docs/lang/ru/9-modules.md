## 1. Файловая структура и адресация модулей

Каждый файл `.ykn` и каждый каталог с файлом точки входа образуют модуль.

### 1.1 Префиксы путей: root, относительные точки и пакеты

Путь в инструкции `load` начинается с префикса одного из трех типов:

| Префикс | Синтаксис | Описание |
| :--- | :--- | :--- |
| `root` | `load root.submod: ...` | Абсолютный путь от корня исходников проекта (`src/`) |
| `.` (1 точка) | `load .fiction: ...` | Относительный путь от текущего каталога файла |
| `..` (2 точки) | `load ..parent_mod: ...` | Относительный путь от родительского каталога |
| `...` (3 точки) | `load ...grandparent: ...` | Относительный путь на два уровня вверх |
| Имя пакета | `load std.io: print` | Внешняя библиотека из `yuki.toml` (`[libs.runtime]`) или стандартная библиотека |

Пример структуры проекта:

```text
my_project/
├── yuki.toml
└── src/
    ├── main.ykn
    ├── helper.ykn
    └── network/
        ├── client.ykn
        └── protocol.ykn
```

Из файла `src/network/client.ykn`:
- `load root.helper: calc` — обращение к `src/helper.ykn` через корень `root`.
- `load .protocol: Packet` — соседний модуль в том же каталоге `network/`.
- `load ..helper: calc` — обращение к модулю этажом выше.
- `load std.io: print` — обращение к зарегистрированному пакету `std`.

### 1.2 Разрешение файлов, пакетов и каталогов (mod.ykn и lib.ykn)

Простыми словами о том, как компилятор находит нужный файл при импорте:

1. **Импорт библиотеки целиком без подмодуля (`load mylib` или `load std`):**  
   Если импортируется библиотека/пакет без указания конкретного подмодуля, компилятор автоматически ищет главную библиотечную точку входа — модуль вида `{libname}.lib` (то есть файл `lib.ykn` в корне пакета). Например:
   - `load std` эквивалентно `load std.lib` (а также эквивалентно `load std: *`). При этом автоматически подгружается `std/lib.ykn`, который реэкспортирует ключевые модули библиотеки.
   - `load mylib` эквивалентно `load mylib.lib` (и `load mylib: *`).
2. **Импорт каталога (`load .folder` или `load root.components`):**  
   Если сегмент пути указывает на каталог (папку), компилятор автоматически ищет в нем файл точки входа каталога — `mod.ykn`. Файл `mod.ykn` собирает и при необходимости реэкспортирует содержимое своего пакета (подобно `__init__.py` в Python или `mod.rs` в Rust). Например:
   - `load std.platformio` эквивалентно `load std.platformio.mod` (и эквивалентно `load std.platformio: *`).
   - `load .subpkg` эквивалентно `load .subpkg.mod` (если `subpkg` — каталог с `mod.ykn`).
   - `load root.components` эквивалентно `load root.components.mod`.
3. **Импорт одиночного файла (`load .helper`):**  
   Если в каталоге лежит файл с расширением `.ykn` (например, `helper.ykn`), компилятор загружает его напрямую (`load .helper` эквивалентно `load .helper: *`).

Порядок разрешения для любого имени `foo`:
1. Одиночный файл: `foo.ykn`.
2. Каталог-модуль: `foo/mod.ykn`.
3. Каталог-библиотека: `foo/lib.ykn`.

Если в одном каталоге одновременно присутствуют и файл `foo.ykn`, и подкаталог `foo/mod.ykn`, **приоритет всегда отдается файлу `foo.ykn`**.

### 1.3 Принудительный импорт каталогов через суффикс !

Если вам необходимо разрешить импорт именно в каталог `foo/mod.ykn` (или `foo/lib.ykn`), проигнорировав существующий одноименный файл `foo.ykn`, после имени импорта указывается восклицательный знак `!`:

```yukino
// Принудительно ищет subpkg/mod.ykn или subpkg/lib.ykn, даже если есть subpkg.ykn
load .subpkg!: helper_fn
load std.platformio!
load fiction.my.slayer.araragi!
load root.mushoku.tensei!: peak
```

## 2. Декларация load и формы импорта

Инструкция `load` поддерживает точечный импорт символов с переименованием, импорт всего пакета, а также импорт по префиксу или суффиксу.

### 2.1 Точечный импорт символов и псевдонимы (as)

Через двоеточие перечисляются импортируемые идентификаторы. Ключевое слово `as` задает локальный псевдоним:

```yukino
// Импорт одной функции
load root.math: calculate

// Импорт с локальным переименованием
load root.math: calculate as calc

// Импорт нескольких символов с соответствующими псевдонимами:
// сначала полный список символов через запятую, затем одно
// ключевое слово as с псевдонимами в том же количестве
load root.math: add, multiply as my_add, my_mul
```

> [!WARNING]
> Список символов и список псевдонимов разделяются единственным ключевым словом `as`: форма `load .m: add as a, mult as b` (переименование после каждого символа) не поддерживается. Число псевдонимов после `as` обязано совпадать с числом импортируемых символов, иначе компилятор выдаст ошибку E0304.

### 2.2 Импорт всего пакета и импорт по префиксу или суффиксу

Отсутствие двоеточия со списком символов в инструкции `load` компилятор распознает как импорт всех публичных сущностей модуля (эквивалентно `: *`):

- `load lib.anymod` полностью эквивалентно `load lib.anymod: *`
- `load std.io` полностью эквивалентно `load std.io: *`
- `load std` полностью эквивалентно `load std: *` (и `load std.lib`)

Также в секции символов после двоеточия можно явно указать `*` либо отобрать импортируемые символы по префиксу или суффиксу:

```yukino
// 1. Импорт всего пакета: форма без двоеточия эквивалентна явной звездочке ': *'
load .worker           // эквивалентно load .worker: *
load .worker: *        // импортирует все публичные символы модуля

// 2. Импорт по префиксу: все символы, начинающиеся с 'work' (work_a, work_b, worker_init)
load .worker: work*

// 3. Импорт по суффиксу: все символы, оканчивающиеся на 'Handler'
load .handlers: *Handler
```

> [!WARNING]
> Компилятор запрещает комбинировать импорт всего пакета, а также импорт по префиксу или суффиксу (`*`, `prefix*`, `*suffix`) с псевдонимами `as`. Попытка написать `load .worker: work* as my_work` приведет к ошибке компиляции E0304.

### 2.3 Импорт всех модулей каталога

Импорт всех сущностей и отбор по префиксу допустимы не только в списке символов, но и в самом пути модулей:

```yukino
// Импортирует все модули каталога models (user.ykn, order.ykn, item.ykn)
load .models.*

// Импортирует модули каталога suites, начинающиеся с 'test_'
load .suites.test_*
```

Компилятор автоматически обходит каталог, отфильтровывает служебные файлы `mod.ykn` и `lib.ykn` и подключает каждый подходящий модуль.

### 2.4 Импорт всего пакета без двоеточия

Если после пути не указано двоеточие с символами, модуль загружается целиком, и все его открытые сущности сразу становятся доступны в текущей области видимости:

```yukino
load std.io

fun main() {
    print("Hello, Yukino!\n")
}
```

> [!NOTE]
> Если вам требуется обращаться к символам через префикс или задать короткое имя модулю/символу во избежание коллизий имен, используйте декларацию `alias` (см. раздел 3).

## 3. Декларация alias и пространства имен ::

### 3.1 Двойное двоеточие :: и встроенные префиксы

Оператор `::` позволяет обращаться к сущностям через пути пространств имен. Это исключает двусмысленность и коллизии имен при совпадении идентификаторов:

1. **Пространства имен модулей (`std::io::`):**  
   После загрузки модуля (`load std.io`) доступ к его публичным символам возможен напрямую через полный путь:
   ```yukino
   load std.io

   fun main() {
       std::io::print("Hello via qualified path!\n")
   }
   ```

2. **Интринсики компилятора (`rt::`):**  
   Все встроенные интринсики языка (`cast`, `exit`, `args`, `raw_args`, `panic`, `assert`, `ptr_of`, `typeof!`) могут опционально вызываться через префикс `rt::`:
   ```yukino
   fun main() {
       set text = rt::cast(100, "string")
       set t = rt::typeof!(text)
       rt::exit(0)
   }
   ```

3. **C ABI функции (`extern::`):**  
   Функции, объявленные через `cfun` или блоки `externc`, могут опционально вызываться через префикс `extern::`. Это позволяет явно вызвать C-функцию, даже если в программе объявлена одноименная функция Yukino:
   ```yukino
   externc {
       cfun puts(s: ptr<c_char>) -> c_int
   }

   // Одноименная функция Yukino
   fun puts(msg: string) {
       // Логика на Yukino
   }

   fun main() {
       // Явный вызов внешней C-функции:
       extern::puts(null)
       // Вызов функции Yukino:
       puts("Hello")
   }
   ```

### 3.2 Декларация alias

Декларация `alias` позволяет создавать короткие псевдонимы на верхнем уровне модуля для пространств имен или конкретных символов:

```yukino
// 1. Псевдоним для пространства имен:
alias std::io as io

// 2. Псевдоним для символа из пространства имен (через символ '#'):
alias std::io#print as println

// 3. Псевдоним для локального идентификатора:
alias heavy_internal_name as fast_name

fun main() {
    println("Using aliased print\n")
}
```

## 4. Модификаторы видимости и реэкспорт

### 4.1 Приватность по умолчанию и модификатор public

В Yukino действует строгое правило: **все сущности модуля по умолчанию приватны**.

Чтобы функция, структура, класс или константа стали доступны другим модулям через `load`, они обязаны иметь модификатор `public`:

```yukino
// Файл src/calc.ykn

// Приватная функция: не видна за пределами calc.ykn
fun helper() -> int32 {
    return 1
}

// Публичная функция: доступна для других файлов
public fun sum(a: int32, b: int32) -> int32 {
    return a + b + helper()
}

// Публичная структура с публичными полями
public struct Point {
    public x: float64
    public y: float64
}
```

Попытка импортировать приватный идентификатор будет отклонена резолвером с ошибкой `E0303: symbol is not public`.

### 4.2 Реэкспорт символов: public load

Пакет может реэкспортировать символы из внутренних модулей наружу с помощью комбинации `public load`. Это ключевой механизм формирования фасадных интерфейсов библиотек (`lib.ykn`) и подпакетов (`mod.ykn`):

```yukino
// Файл src/network/lib.ykn (фасад пакета)

// 1. Точечный реэкспорт конкретных типов:
// Пользователи пакета могут написать: load network: Client, Packet
public load .client: Client
public load .protocol: Packet

// 2. Полный реэкспорт всех публичных символов дочернего модуля:
// Обе формы эквивалентны:
public load .transport      // эквивалентно public load .transport: *
public load .transport: *
```

#### Как работает `public load`

1. **Публичность в текущем модуле:** Символы, импортированные через `public load`, добавляются в таблицу символов текущего модуля как экспортируемые (`is_reexported = true`). Для любого внешнего файла, подключающего этот модуль, они выглядят так, словно объявлены прямо в нем с ключевым словом `public`.
2. **Различие между `load` и `public load`:**  
   - Обычный `load` (приватный): символы доступны только внутри текущего файла. Если модуль `B` делает `load A`, а модуль `C` делает `load B`, модуль `C` **не имеет доступа** к символам модуля `A`.
   - `public load`: модуль `B` делает `public load A`, после чего модуль `C` при импорте `load B` получает доступ ко всем реэкспортированным символам `A`.
3. **Эквивалентность без двоеточия:**  
   Конструкция `public load .submod` полностью эквивалентна `public load .submod: *` — она реэкспортирует абсолютно все открытые символы дочернего подмодуля.

> [!TIP]
> В каждом подпакете (каталоге) создавайте файл `mod.ykn` с директивами `public load .submod`, реэкспортирующими все открытые символы дочерних модулей. Это обеспечивает единообразный модульный интерфейс для потребителей пакета.

## 5. Условная компиляция и атрибуты модулей

Элементы модуля могут снабжаться атрибутами условной компиляции, зависящими от целевой архитектуры, операционной системы или фич `yuki.toml`. Полный справочник по всем атрибутам компилятора представлен в документе [13. Атрибуты компилятора](13-attributes.md).

Условные атрибуты принимают строку или массив строк. При этом `#[arch]` допускает ровно одно значение из списка `x86_64`, `arm64`, `arm`, а `#[feature]` с несколькими значениями требует наличия всех перечисленных фич одновременно.

```yukino
// Компилируется исключительно на архитектуре x86_64
#[arch("x86_64")]
public fun fast_simd() -> int32 {
    return 1
}

// Отрицание: компилируется на всех архитектурах кроме arm
#[!arch("arm")]
public fun non_arm() {
    space
}

// Условие по полному таргету (триплету): строка или массив строк
#[target("x86_64-unknown-linux-gnu")]
public fun linux_only() {
    space
}

// Проверка фичи из манифеста yuki.toml
#[feature("crypto")]
public fun decrypt_buffer() {
    space
}

// Атрибуты кодогенератора LLVM
#[inline]
public fun inlined_op(x: int32) -> int32 {
    return x * 2
}

struct AbortError {
    message: string
    code: int32
}

#[cold]
#[noreturn]
public fun abort_system() {
    panic(AbortError {
        message: "critical error",
        code: 999,
    })
}
```
