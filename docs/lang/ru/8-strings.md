## 1. Внутреннее представление и семантика строк

### 1.1 Что такое строка под капотом (Дескриптор)
Строка типа `string` в Yukino — это не отдельный объект в куче с заголовками и метаданными, а компактный **дескриптор** размером ровно 16 байт на 64-битной системе (в LLVM IR: `{ ptr, i64 }`):

```text
Строка: { ptr: указатель на байты (8 байт), len: длина в байтах (8 байт) }
```

Дескриптор работает следующим образом:
- `ptr` — это 64-битный абсолютный адрес в памяти, где расположен первый байт текста.
- `len` — это количество байт в строке.
- Конец строки в памяти определяется простым вычислением: `ptr + len`. 

Благодаря известной длине получение размера `.len()` и построение срезов выполняются мгновенно за $O(1)$ без необходимости сканировать строку в поисках нулевого байта `\0`. Строки могут безопасно содержать нулевые байты внутри своего текста.

### 1.2 Строка как Copy-тип: почему строки больше не аффинные
В ранних версиях Yukino строка считалась аффинным типом (Affine Type) с семантикой перемещения (`Move`). Из-за этого при любой передаче строки в функцию (`println(s)`) или присваивании в другую переменную исходная переменная безвозвратно сгорала, требуя от разработчика писать `ref s: string` и `call(ref s)` на каждом шагу. Было решено отказаться от этой искусственной сложности и перевести `string` в категорию тривиально копируемых типов (**Copy-типов**).

Поскольку строки в Yukino **строго неизменяемы (immutable)**:
- При передаче в функцию или присваивании `set b = a` копируются только **16 байт дескриптора** (значения регистров CPU).
- Исходная переменная остаётся полностью валидной и не сгорает.
- Для чтения строк больше не требуется указывать ключевое слово `ref`.

### 1.3 Литералы в `.rodata` против динамических строк в ОЗУ
Байты строк могут находиться в двух разных областях памяти, но для программиста они работают одинаково через один и тот же 16-байтный дескриптор:

1. **Строковые литералы (`"константы"` и `static`):**  
   Байты таких строк компилятор зашивает напрямую в секцию констант исполняемого файла (`.rodata`). Операционная система загружает эту секцию в ОЗУ в режиме **только для чтения (Read-Only)**. Они живут в памяти всё время работы программы.
2. **Динамические строки (`read_line()`, `cast(...)`):**  
   Создаются во время работы программы. Их байты выделяются в оперативной памяти — в активном **региональном bump-аллокаторе (Region)** текущей функции. Выделение памяти занимает 1 такт CPU (сдвиг указателя арены). Когда функция или явный блок `region { ... }` завершается, вся выделенная динамическая память освобождается мгновенно за $O(1)$.

### 1.4 Что происходит при переприсвоении и конкатенации
- **Конкатенация (`a + b`):**  
  Оператор `+` вычисляет сумму длин `a.len() + b.len()`, выделяет новый непрерывный блок памяти в текущем регионе ОЗУ, копирует туда байты строки `a`, затем байты строки `b`, и возвращает новый 16-байтный дескриптор.
- **Переприсвоение (`rewrite s = s + "!"`):**  
  При переприсвоении старый буфер в памяти не модифицируется и не удаляется вручную (он безопасно живёт в регионе до выхода из контекста). Мутируется **сама переменная `s` на стеке**: её поля `ptr` и `len` перезаписываются адресом и длиной нового блока памяти.

### 1.5 Что происходит при вызове .cp()
Метод `.cp()` для строк возвращает **исходный дескриптор без выделения новой памяти и без копирования байтов**.  
Так как строки неизменяемы, два дескриптора могут безопасно указывать на один и тот же буфер в памяти. Физическое выделение нового независимого буфера в регионе метод `.cp()` выполняет только для мутабельных срезов `T[]` и `bytes`.

### 1.6 Как работает преобразование в строку через cast(x, "string")
Интринсик компилятора `cast(значение, "string")` преобразует данные в строку:
- **Целые числа (`int8`..`int64`, `uint8`..`uint64`):** форматирует число в десятичный текст, выделяет память под цифры в текущем регионе ОЗУ и возвращает дескриптор.
- **Дробные числа (`float32`, `float64`):** форматирует число с плавающей точкой в строковый вид.
- **Символы (`char`):** кодирует 32-битный код символа Unicode в последовательность от 1 до 4 байт UTF-8 в текущем регионе.
- **Байтовые срезы (`bytes`):** выполняет Zero-Copy преобразование — берёт указатель `ptr` и длину `len` массива байт и создаёт дескриптор `string` без повторного копирования буфера (валидация UTF-8 не выполняется).
- **Указатели (`ptr<T>`):** форматирует числовое значение адреса в шестнадцатеричную строку вида `"0x7ffd1234"`.

## 2. Литералы строк и байтов

### 2.1 Обычные и многострочные строки

```yukino
// Однострочная строка
set greeting = "Привет, Yukino!"

// Многострочная строка через тройные кавычки (сохраняет переводы строк и форматирование)
set query = """
SELECT id, username, email
FROM users
WHERE active = true
ORDER BY id DESC
"""
```

### 2.2 Escape-последовательности

Поддерживаются следующие escape-последовательности:
- `\n` — перенос строки;
- `\t` — табуляция;
- `\r` — возврат каретки;
- `\\` — обратный слэш;
- `\"` — двойная кавычка;
- `\'` — одинарная кавычка;
- `\0` — нулевой байт;
- `\$` — символ доллара (экранирует запуск интерполяции `${`);
- `\xHH` — 8-битный шестнадцатеричный байт (ровно две шестнадцатеричные цифры);
- `\u{H...}` — код Unicode (от 1 до 6 шестнадцатеричных цифр в фигурных скобках).

Любая другая последовательность после `\` вызывает ошибку компиляции E0108.

### 2.3 Данные типа bytes

Отдельного синтаксиса байтовых литералов вида `b"..."` в языке нет. Значение типа `bytes` получается одним из следующих способов:

```yukino
// Конвертация строки в bytes (буфер не копируется, cap = len)
set header: bytes = cast("PNG\r\n\x1a\n", "bytes")

// Встраивание бинарного файла целиком на этапе компиляции
static FONT_DATA: bytes = include_bytes!("assets/font.ttf")
```

При конвертации обратно (`cast(data, "string")`) UTF-8 валидация не выполняется.

## 3. Строковая интерполяция: ${...}

Yukino поддерживает интерполяцию произвольных выражений прямо внутри строковых литералов через `${expr}`:

```yukino
set name = "Юкино Юкиношита"
set age = 17

// Встроенная интерполяция переменных и вычислений
set message = "Привет, ${name}! Через 5 лет тебе будет ${age + 5}."

set couple = { x: "Хикигая", y: "Юкино" }
set result = "Итог: ${couple.x} ${couple.y}"
```

Компилятор автоматически преобразует интерполируемые значения в строки без привлечения внешних библиотек. Поддерживаются целые числа, числа с плавающей точкой, `char`, а также указатели (форматируются в шестнадцатеричный адрес вида `0x...`). Значение типа `bool` внутри интерполяции не поддерживается и приводит к ошибке компиляции `unsupported bool cast between \`bool\` and \`string\`` — предварительно преобразуйте его через `cast(flag, "int32")`.

## 4. Встроенные операции ядра компилятора

Все нижеперечисленные операции работают на уровне самого компилятора и доступны в любых файлах без импорта стандартной библиотеки.

### 4.1 Длина, пустота и сырой указатель (.len, .is_empty, .as_ptr)

```yukino
set s = "Yukino"

// Число байт за O(1)
set byte_count: int64 = s.len()

// Проверка на пустую строку (len == 0)
set nothing: bool = s.is_empty()

// Указатель на первый байт буфера в памяти (тип ptr<uint8>)
set raw_ptr = s.as_ptr()
```

Эти три метода — единственные встроенные методы строк. Методы `.cap()`, `.push()`, `.pop()` и другие существуют только у срезов `T[]` и `bytes`; для строк они не определены.

### 4.2 Индексация байт

Индексация строки квадратными скобками `s[i]` возвращает байт по смещению с типом `uint8`:

```yukino
set word = "ABC"
set first_byte: uint8 = word[0] // 65 (код 'A')
```

> [!WARNING]
> Прямая индексация `s[i]` компилируется **без проверки границ**: компилятор генерирует обращение по смещению без сравнения с `len`. Выход индекса за пределы строки не вызывает панику, а приводит к неопределённому поведению (чтение чужой памяти). Для безопасного доступа с проверкой границы используйте функцию `byte_at` из `std.strings` (или проверяйте длинну с помощью len).

### 4.3 Срезы подстрок: s[start..end]

Срез строки возвращает подстроку типа `string`, указывающую на диапазон байт исходной строки. Поддерживаются открытые, полуоткрытые и замкнутые диапазоны:

```yukino
set text = "Hello, world!"

set greeting = text[0..5]   // "Hello" (индексы от 0 до 4)
set exact    = text[0..=4]  // "Hello" (включая индекс 4)
set rest     = text[7..]    // "world!" (от индекса 7 до конца)
set prefix   = text[..5]    // "Hello" (от начала до 4)
set whole    = text[..]     // "Hello, world!" (вся строка)
```

> [!WARNING]
> Как и прямая индексация, срезы `s[start..end]` компилируются **без проверки границ**: длина результата вычисляется как `end - start`, а указатель — как смещение от начала буфера. Некорректные границы (например `end > len`) не вызывают панику, а приводят к неопределённому поведению. Для безопасных срезов используйте функцию `slice`/`substring` из `std.strings`.

### 4.4 Конкатенация и сравнение

Оператор `+` объединяет строки, выделяя новую строку в текущем регионе:

```yukino
set part1 = "Yukino "
set part2 = "Yukinoshita"

set full_name = part1 + part2 // "Yukino Yukinoshita"
```

Операторы `==` и `!=` выполняют сравнение строк:

```yukino
if full_name == "Yukino Yukinoshita" {
    // строки равны
}

if part1 != part2 {
    // строки не равны
}
```

Сравнение оптимизировано: сначала выполняется проверка равенства длины строк ($O(1)$) и проверка совпадения буфера; побайтовое сравнение содержимого вызывается только при совпадении длины.

### 4.5 Копирование строк (.cp)

Поскольку строка в Yukino представляет собой легковесный дескриптор `{ ptr, len }`, простое присваивание `set b = a` не дублирует данные, а лишь копирует дескриптор, ссылаясь на тот же неизменяемый буфер в памяти.

Для строк метод `.cp()` также возвращает исходный дескриптор без копирования: так как строки неизменяемы, физическое дублирование буфера не требуется. Реальное глубокое копирование в новый буфер текущего региона памяти `.cp()` выполняет только для срезов `T[]` и `bytes`:

```yukino
set original = "Yukino"
set clone = original.cp() // тот же неизменяемый буфер; для строк копия не нужна

set data: bytes = cast("raw", "bytes")
set data_copy = data.cp() // новый независимый буфер памяти с полной копией байт
```

> [!TIP]
> Подробнее о внутреннем устройстве `.cp()`, а также о работе с емкостью и сырыми указателями срезов см. в документе [Встроенные интринсики и методы ядра (12-intrinsics.md)](12-intrinsics.md#6-встроенные-методы-срезов-массивов-строк-и-байтов).

## 5. Совместимость со строками языка C

Си-библиотеки ожидают строки вида `ptr<char>`, завершающиеся нулевым байтом (`\0`). Буферы строковых литералов Yukino уже завершаются нулевым байтом, поэтому для передачи литерала в C-функцию достаточно метода `.as_ptr()`.

### 5.1 Передача строк в C через .as_ptr()

```yukino
externc {
    |cdecl|
    cfun write(fd: int32, buf: ptr<uint8>, count: int64) -> int64;
}

fun main() {
    set text = "Hello, C!\n" // литерал завершается \0 в памяти
    write(1, text.as_ptr(), text.len())
}
```

`.as_ptr()` возвращает указатель типа `ptr<uint8>`; при необходимости он приводится к `ptr<char>` через `cast` (преобразование между типами указателей — это переименование без кода).

> [!WARNING]
> Гарантированный нулевой байт на конце есть только у литералов. Строки, собранные в рантайме (например, конкатенацией), могут не содержать завершающий `\0` — передавайте их в C вместе с длиной (`ptr`, `len`), как в примере выше.

### 5.2 cast между строкой и указателем

Интринсик `cast` между `string` и `ptr<T>` **не выполняет конвертацию C-строк**. Его реальная семантика — преобразование адреса в текст и обратно:

```yukino
// Строка интерпретируется как текстовое представление адреса:
// допускается префикс "0x" и пробелы по краям; при пустой или
// некорректной строке возвращается нулевой указатель
set p: ptr<uint8> = cast("0x7ffd1234", "ptr<uint8>")

// Указатель форматируется в строку вида "0x7ffd1234"
set text: string = cast(p, "string")
```
